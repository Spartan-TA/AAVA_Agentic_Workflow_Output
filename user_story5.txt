Title: Create Employee Domain Model

User Story: As an HR manager I want to manage employee records with fields like name, badgeId, role, department, shiftGroup, hireDate, and status So that I have a single source of truth for employee data

Acceptance Criteria:
Scenario: Employee CRUD operations
Given the employee API is available
When I create, update, or delete an employee
Then the changes are reflected in the database and badgeId uniqueness is enforced

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Database setup
- Notes: Support soft-delete and audit logging
