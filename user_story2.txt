Title: Employee Master Data CRUD Operations

User Story: As an HR manager I want to create, read, update, and delete employee records So that we maintain a single source of truth for all warehouse employees.

Acceptance Criteria:
Scenario: Employee CRUD
Given I have HR role access
When I POST/GET/PUT/PATCH/DELETE employee data via API
Then the employee record is correctly created, updated, retrieved, or deleted

Scenario: Unique badge enforcement
Given I am adding a new employee
When I enter a badgeId that already exists
Then the system rejects the entry with a validation error

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project scaffolding (E01)
- Notes: Soft-delete supported; pagination/filtering; OpenAPI schemas with examples.
