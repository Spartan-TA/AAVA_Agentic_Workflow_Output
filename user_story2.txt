Title: Employee CRUD API - Create Employee

User Story: As an HR I want to create a new employee record with all required fields So that new hires are registered in the system.

Acceptance Criteria:
Scenario: Valid employee creation
Given I have valid employee details (name, badgeId, role, department, shiftGroup, hireDate, status)
When I POST to /employees
Then the employee is created and returned with a unique badgeId

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique

Title: Employee CRUD API - Update Employee

User Story: As an HR I want to update employee details So that records remain accurate over time.

Acceptance Criteria:
Scenario: Update employee information
Given an existing employee
When I PUT or PATCH to /employees/{id} with valid changes
Then the employee record is updated

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Only allowed fields are editable

---

Title: Employee CRUD API - Delete (Soft Delete) Employee

User Story: As an HR I want to soft-delete an employee So that terminated employees are not lost but excluded from active lists.

Acceptance Criteria:
Scenario: Soft delete employee
Given an existing employee
When I DELETE /employees/{id}
Then the employee status is set to inactive and record is not removed from the database

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Soft delete only, no hard delete

---

Title: Employee CRUD API - List & Filter Employees

User Story: As an ADMIN I want to list and filter employees by department, role, and status So that I can manage large workforces efficiently.

Acceptance Criteria:
Scenario: Filter employees by department
Given multiple employees exist
When I GET /employees?department=Shipping
Then only employees in Shipping are returned

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Supports pagination
