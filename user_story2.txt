Title: Employee Master Data CRUD APIs

User Story: As an HR manager I want to create, read, update, and delete employee records So that I can maintain accurate and up-to-date employee information

Acceptance Criteria:
Scenario: Create employee record
Given I have valid employee details
When I submit a POST request to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update employee record
Given an existing employee record
When I submit a PUT or PATCH request with updated details
Then the employee record is updated accordingly

Scenario: Delete employee record
Given an employee record exists
When I submit a DELETE request
Then the employee is soft-deleted and excluded from active lists

Scenario: Retrieve employee records
Given employee records exist
When I send a GET request to /employees with filters
Then I receive a paginated and filtered list of employees

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Ensure OpenAPI schemas are provided with examples; enforce unique badgeId; support pagination and filtering.
