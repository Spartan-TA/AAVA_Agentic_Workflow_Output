Title: Employee Master Data CRUD Operations

User Story: As an HR administrator I want to manage employee records (create, read, update, delete) so that there is a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee details
  When I submit a POST request to /employees
  Then a new employee is created with a unique badgeId

Scenario: Update employee
  Given an existing employee
  When I send a PUT or PATCH request with updated fields
  Then the employee record is updated accordingly

Scenario: Delete employee (soft-delete)
  Given an existing employee
  When I send a DELETE request
  Then the employee is marked as deleted but not removed from the database

Scenario: List and filter employees
  Given multiple employees exist
  When I send a GET request with pagination and filters
  Then I receive a paginated, filtered list of employees

Scenario: OpenAPI documentation
  Given the API is documented
  When I view the OpenAPI schema
  Then all endpoints and examples are present

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Enforce unique badgeId and support soft-delete. Ensure API schemas are up to date.
