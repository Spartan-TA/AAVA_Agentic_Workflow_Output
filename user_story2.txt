Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records (create, read, update, delete) with unique badge IDs and relevant attributes so that there is a single source of truth for all warehouse employee data.

Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee details
  When I submit a POST request to /employees
  Then a new employee is created with a unique badgeId

Scenario: Update employee
  Given an existing employee
  When I send a PUT or PATCH request with updated details
  Then the employee record is updated accordingly

Scenario: Delete employee
  Given an existing employee
  When I send a DELETE request
  Then the employee is soft-deleted and excluded from active queries

Scenario: List employees
  Given multiple employees exist
  When I send a GET request to /employees with filters
  Then I receive a paginated, filtered list of employees

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project Scaffolding & Domain Setup
- Notes: OpenAPI schemas must be provided with examples; ensure soft-delete and unique badgeId enforcement.
