### E04: Time & Attendance (Clock In/Out)

**User Story 1: Employee Clock-In/Out API**
- User Story: As a worker, I want to clock in and out via an endpoint So that my attendance is accurately recorded.
- Acceptance Criteria:
  - Scenario: Valid clock-in
    - Given a scheduled shift
    - When I POST to /attendance/clock-in with valid location/device
    - Then my clock-in is recorded and associated with my shift
  - Scenario: Geofence validation
    - Given a clock-in from outside the allowed area
    - When I submit the request
    - Then the request is rejected
- Priority: High
- Story Points: 5
- Dependencies: E02, E03
- Notes: Device capture required.

**User Story 2: Missed Punches and Corrections Workflow**
- User Story: As a worker, I want to request corrections for missed punches So that my attendance records are accurate.
- Acceptance Criteria:
  - Scenario: Missed punch correction
    - Given a missed clock-in/out
    - When I submit a correction request
    - Then an approval task is created for my supervisor
  - Scenario: Approval workflow
    - Given a pending correction
    - When my supervisor approves it
    - Then my attendance record is updated
- Priority: High
- Story Points: 3
- Dependencies: E02, E03
- Notes: All corrections must be auditable.
