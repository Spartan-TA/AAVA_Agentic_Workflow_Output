### E04 - Time & Attendance (Clock In/Out)

**User Story 1: Clock-In Endpoint**
- Title: Employee Clock-In API
- User Story: As a worker, I want to clock in with device and location capture so that my attendance is accurately recorded.
- Acceptance Criteria:
  - Given valid credentials, When I POST to /attendance/clock-in, Then my clock-in is recorded with device and location.
  - Given invalid location, When I clock in, Then the request is rejected.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E02, E03, Notes: Geofence optional.

**User Story 2: Clock-Out Endpoint**
- Title: Employee Clock-Out API
- User Story: As a worker, I want to clock out so that my work hours are tracked.
- Acceptance Criteria:
  - Given a clocked-in employee, When I POST to /attendance/clock-out, Then my clock-out is recorded and hours are calculated.
  - Given missing clock-in, When I clock out, Then a missed punch is flagged.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Validate shift association.

**User Story 3: Missed Punch Correction Workflow**
- Title: Attendance Correction Request
- User Story: As a worker, I want to request corrections for missed punches so that my attendance is accurate.
- Acceptance Criteria:
  - Given a missed punch, When I submit a correction, Then an approval task is created for my supervisor.
  - Given an approved correction, When I check my attendance, Then the record is updated.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E02, E03, Notes: Approval workflow.

**User Story 4: Attendance Reporting**
- Title: Daily Attendance Report Export
- User Story: As a supervisor, I want to export daily attendance reports in CSV so that I can review and share attendance data.
- Acceptance Criteria:
  - Given attendance data, When I request a CSV export, Then the file is generated with all relevant fields.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Include totals.
