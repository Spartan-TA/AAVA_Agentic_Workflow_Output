Title: Enforce Unique badgeId and Soft-Delete for Employees

User Story: As a system administrator I want to ensure each employee has a unique badgeId and support soft-delete So that employee records are accurate and recoverable if deleted by mistake.

Acceptance Criteria:
Scenario: Unique badgeId enforcement
  Given an employee record is being created
  When I submit a badgeId that already exists
  Then the system should reject the creation with an error
Scenario: Soft-delete employee record
  Given an employee exists
  When I DELETE /employees/{id}
  Then the employee record should be marked as inactive but not removed from the database
Scenario: Restore soft-deleted employee
  Given an employee record is soft-deleted
  When I PATCH to restore the employee
  Then the employee record should become active again

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Employee CRUD APIs
- Notes: Ensure audit trail for delete/restore actions.
