### Epic E03: Role Based Access Control (RBAC)

**User Story 1: Implement Role Definitions**
Title: Define User Roles in System
User Story: As a system admin, I want roles (ADMIN, HR, SUPERVISOR, WORKER) defined so that permissions can be managed.
Acceptance Criteria:
Scenario: Roles available
Given the system is running
When I assign a role to a user
Then the user has corresponding permissions
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Store roles in DB or config

**User Story 2: Endpoint Security Enforcement**
Title: Secure Endpoints by Role
User Story: As a developer, I want endpoints secured by role so that only authorized users can perform sensitive actions.
Acceptance Criteria:
Scenario: Unauthorized access blocked
Given a user without ADMIN role
When they POST to `/employees`
Then they receive a 403 Forbidden response
Priority: High
Story Points: 3
Dependencies: E01, E02
Notes: Cover all sensitive endpoints

**User Story 3: Row-Level Security**
Title: Enforce Row-Level Security
User Story: As a supervisor, I want access limited to my team's records so that I cannot view or edit other teams.
Acceptance Criteria:
Scenario: Supervisor access limited
Given a supervisor user
When they GET `/employees`
Then only employees in their team are returned
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Map supervisors to teams

**User Story 4: API Key/OAuth2 Toggle**
Title: Support API Key and OAuth2 Authentication
User Story: As a developer, I want to toggle between API key and OAuth2 authentication via config so that integration is flexible.
Acceptance Criteria:
Scenario: Auth mode toggled
Given the config is set to API key
When I authenticate with an API key
Then access is granted per role
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Document config options

**User Story 5: Security Test Coverage**
Title: Cover Security Rules with Automated Tests
User Story: As a QA engineer, I want automated tests for security rules so that unauthorized actions are prevented.
Acceptance Criteria:
Scenario: Security tests pass
Given the test suite runs
When security tests execute
Then unauthorized and forbidden actions are correctly blocked
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Include edge cases
