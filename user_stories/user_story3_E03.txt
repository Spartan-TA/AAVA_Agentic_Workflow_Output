### E03 - Role Based Access Control (RBAC)

**Title:** Role-Based Endpoint Security
User Story: As an admin I want endpoints secured by role So that only authorized users can perform sensitive actions
Acceptance Criteria:
Scenario: Unauthorized access
Given a user without HR role
When they POST to `/employees`
Then they receive 403 Forbidden
Scenario: Admin full access
Given an ADMIN user
When they access any endpoint
Then all actions are permitted
Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: E01, E02
- Notes: Security rules covered by tests

---

**Title:** Row-Level Security for Supervisors
User Story: As a supervisor I want to access only my team's records So that privacy is maintained
Acceptance Criteria:
Scenario: Supervisor access
Given a supervisor
When they GET `/employees`
Then only their team's records are returned
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Row-level constraints enforced

---

**Title:** API Key/OAuth2 Toggle
User Story: As a system admin I want to toggle between API key and OAuth2 security So that integration partners can use preferred auth
Acceptance Criteria:
Scenario: Toggle authentication
Given the config is set to API key
When an API request is made
Then API key is required
Scenario: Toggle to OAuth2
Given the config is set to OAuth2
When an API request is made
Then OAuth2 token is required
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Configurable at runtime

---

**Title:** Security Test Coverage
User Story: As a QA engineer I want automated tests for security rules So that unauthorized actions are reliably blocked
Acceptance Criteria:
Scenario: Test unauthorized access
Given a test user
When they attempt forbidden actions
Then tests fail as expected
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Test coverage required for compliance
