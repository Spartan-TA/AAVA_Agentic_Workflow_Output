Title: Implement Employee CRUD APIs

User Story: As an HR manager I want to create, read, update, and delete employee records via APIs So that I can maintain a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Create employee record
  Given I have valid employee data
  When I POST to /employees
  Then a new employee record should be created with a unique badgeId
Scenario: Read employee records
  Given employee records exist
  When I GET /employees
  Then I should receive a paginated list of employees
Scenario: Update employee record
  Given an employee exists
  When I PUT/PATCH to /employees/{id}
  Then the employee record should be updated
Scenario: Delete employee record
  Given an employee exists
  When I DELETE /employees/{id}
  Then the employee record should be soft-deleted
Scenario: Filtering and pagination
  Given multiple employee records exist
  When I apply filters and pagination
  Then only matching records are returned

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project scaffolding
- Notes: Ensure OpenAPI schemas are provided with examples.
