Title: Implement Employee Master Data CRUD APIs

User Story: As an HR Manager I want to create, read, update, and delete employee records via APIs so that I can maintain an accurate and up-to-date employee database for the warehouse.

Acceptance Criteria:
Scenario: Create Employee Record
  Given I have valid employee data
  When I send a POST request to /employees
  Then a new employee record is created and a unique badgeId is assigned

Scenario: Read Employee Records
  Given employee records exist
  When I send a GET request to /employees
  Then I receive a paginated list of employee records with filtering options

Scenario: Update Employee Record
  Given an employee record exists
  When I send a PUT or PATCH request with updated data
  Then the employee record is updated accordingly

Scenario: Delete Employee Record
  Given an employee record exists
  When I send a DELETE request
  Then the employee record is soft-deleted and not shown in active lists

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project scaffolding (E01)
- Notes: Ensure OpenAPI schemas are provided with examples; enforce unique badgeId; support soft-delete.
