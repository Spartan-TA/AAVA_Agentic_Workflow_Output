### E03: Role-Based Access Control (RBAC)

**User Story 3.1**
Title: Implement Role-Based Endpoint Security

User Story: As a system admin I want endpoints secured by user role So that only authorized users can access sensitive data.

Acceptance Criteria:
Scenario: Unauthorized access
Given a user without HR role
When they access /employees
Then they receive 403 Forbidden

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Roles: ADMIN, HR, SUPERVISOR, WORKER

---

**User Story 3.2**
Title: Method-Level Security for Sensitive Operations

User Story: As a developer I want method-level security annotations So that only permitted roles can invoke critical business logic.

Acceptance Criteria:
Scenario: Restricted method call
Given a SUPERVISOR user
When they call an ADMIN-only method
Then access is denied

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03.1
- Notes: Use @PreAuthorize or equivalent

---

**User Story 3.3**
Title: Row-Level Security for Team Data

User Story: As a supervisor I want to see only my team's employee records So that I cannot access other teams' data.

Acceptance Criteria:
Scenario: Team data isolation
Given a SUPERVISOR user
When they GET /employees
Then only employees in their team are returned

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03.1
- Notes: Team assignment must be modeled

---

**User Story 3.4**
Title: Configurable Auth Mechanism (API Key/OAuth2)

User Story: As a system admin I want to toggle between API key and OAuth2 authentication So that integration is flexible.

Acceptance Criteria:
Scenario: Auth toggle
Given a config change
When I switch from API key to OAuth2
Then endpoints require the selected auth method

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03.1
- Notes: Document config steps
