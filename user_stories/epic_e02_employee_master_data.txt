Title: Employee Domain CRUD API

User Story: As an HR I want to create, read, update, and delete employee records via API So that employee data is managed centrally

Acceptance Criteria:
Scenario: Create employee
Given valid employee data
When I POST to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update employee
Given an existing employee
When I PUT updated data to /employees/{id}
Then the employee record is updated

Scenario: Soft-delete employee
Given an active employee
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project scaffolding
- Notes: Supports pagination and filtering

Title: Enforce Unique Badge ID

User Story: As an HR I want badgeId to be unique for each employee So that duplicate records are prevented

Acceptance Criteria:
Scenario: BadgeId uniqueness
Given an existing badgeId
When I try to create another employee with the same badgeId
Then the system rejects the request with a validation error

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Employee CRUD API
- Notes: Validation covered by unit tests
