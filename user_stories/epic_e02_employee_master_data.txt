EPIC E02: EMPLOYEE MASTER DATA (CRUD)

===========================================

Title: Employee CRUD API

User Story: As an HR manager I want to create, read, update, and delete employee records So that I can maintain accurate employee master data

Acceptance Criteria:

Scenario: Create employee
Given I have valid employee data
When I POST to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update employee
Given an employee exists
When I PUT/PATCH to /employees/{id}
Then the employee record is updated

Scenario: Delete employee
Given an employee exists
When I DELETE /employees/{id}
Then the employee is soft-deleted

Scenario: List employees
Given employees exist
When I GET /employees with pagination and filters
Then I receive a paginated, filtered list

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Enforce unique badgeId, support soft-delete

Title: Employee DTOs and OpenAPI Documentation

User Story: As a developer I want to define web DTOs and OpenAPI schemas for employee APIs So that API consumers have clear documentation and examples

Acceptance Criteria:

Scenario: DTO definition
Given the employee domain model
When I generate DTOs
Then all API endpoints use DTOs for input/output

Scenario: OpenAPI schema
Given the APIs are implemented
When I access the API docs
Then schemas and example payloads are present

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Employee CRUD API
- Notes: Use Swagger/OpenAPI for documentation
