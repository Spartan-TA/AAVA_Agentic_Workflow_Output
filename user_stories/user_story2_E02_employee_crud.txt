### Epic E02: Employee Master Data (CRUD)

**User Story 1**
Title: Create Employee Record
User Story: As an HR, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centralized.
Acceptance Criteria:
Scenario: Employee creation
Given valid employee data
When I POST to /employees
Then a new employee is created with a unique badgeId
Additional Details:
Priority: High
Story Points: 5
Dependencies: E01
Notes: badgeId must be unique.

**User Story 2**
Title: Update Employee Details
User Story: As an HR, I want to update employee details so that records remain accurate.
Acceptance Criteria:
Scenario: Employee update
Given an existing employee
When I PUT/PATCH to /employees/{id}
Then the employee details are updated
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Changes tracked for audit.

**User Story 3**
Title: Soft Delete Employee
User Story: As an ADMIN, I want to soft-delete employees so that historical data is preserved.
Acceptance Criteria:
Scenario: Soft delete
Given an active employee
When I DELETE /employees/{id}
Then the employee status is set to inactive
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: No hard deletes.

**User Story 4**
Title: List Employees with Filtering
User Story: As a SUPERVISOR, I want to list employees with pagination and filtering so that I can manage my team efficiently.
Acceptance Criteria:
Scenario: Employee listing
Given multiple employees
When I GET /employees?department=Shipping
Then only employees in Shipping are returned, paginated
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Filtering by department, role, status.

**User Story 5**
Title: OpenAPI Schema Documentation
User Story: As a DEVELOPER, I want OpenAPI schemas with examples for employee endpoints so that integration is straightforward.
Acceptance Criteria:
Scenario: API documentation
Given employee endpoints
When I view OpenAPI docs
Then all endpoints have schema and example payloads
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Must be updated with every API change.
