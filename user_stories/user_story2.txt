Title: Employee CRUD API

User Story: As an HR manager I want to create, read, update, and delete employee records So that employee data is accurate and up-to-date.

Acceptance Criteria:
Scenario: Employee CRUD operations
Given the Employee domain is defined
When I use the POST/GET/PUT/PATCH/DELETE endpoints
Then employee records are created, retrieved, updated, or soft-deleted as requested

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: E01
- Notes: Unique badgeId enforced; pagination and filtering supported.

Title: Employee Badge ID Uniqueness

User Story: As an HR manager I want to ensure each employee has a unique badgeId So that identification errors are prevented.

Acceptance Criteria:
Scenario: Badge ID uniqueness enforcement
Given I attempt to create an employee with an existing badgeId
When the request is processed
Then the system rejects the creation with a validation error

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: OpenAPI schemas must include examples.
