Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD operations so that there is a single source of truth for all warehouse employee data.

Acceptance Criteria:
Scenario: Employee record management
Given I have access to the employee management interface
When I create, update, or delete an employee
Then the system enforces unique badgeId, supports soft-delete, and provides pagination and filtering
And OpenAPI schemas are available with examples

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Employee fields include name, badgeId, role, department, shiftGroup, hireDate, status.
