Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to create, read, update, and delete employee records So that we maintain a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Employee CRUD operations
Given I have HR role access
When I perform POST/GET/PUT/PATCH/DELETE on /employees
Then the operations should succeed and unique badgeId should be enforced

Scenario: Soft-delete support
Given an employee record exists
When I soft-delete the record
Then it should be excluded from active queries but remain in the database

Scenario: Pagination and filtering
Given multiple employee records exist
When I query with pagination and filters
Then I should receive correct results as per OpenAPI schemas

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Ensure OpenAPI schemas have examples and badgeId uniqueness is validated.
