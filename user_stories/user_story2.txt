Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to create, view, update, and delete employee records So that we have a single source of truth for warehouse employee records

Acceptance Criteria:
Scenario: Create Employee
Given I have HR role access
When I submit a new employee with name, badgeId, role, department, shiftGroup, hireDate, and status
Then the employee is created and badgeId is unique

Scenario: Update Employee
Given an employee exists
When I update their details
Then the changes are saved and reflected in the system

Scenario: Delete Employee
Given an employee exists
When I perform a delete action
Then the employee is soft-deleted and excluded from active lists

Scenario: Pagination and Filtering
Given multiple employees exist
When I request a paginated and filtered list
Then the API returns the correct subset

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Ensure OpenAPI schemas with examples and soft-delete support.
