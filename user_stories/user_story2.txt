Title: Employee Master Data (CRUD)
User Story: As an HR manager I want to manage employee records with CRUD operations so that employee data remains accurate and up-to-date across all systems.
Acceptance Criteria:
Scenario: Manage employee records
Given I have HR permissions
When I create, update, or delete an employee
Then the system enforces unique badgeId, supports soft-delete, and provides pagination and filtering
And OpenAPI schemas are available with examples
Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Ensure all endpoints (POST/GET/PUT/PATCH/DELETE /employees) are implemented and tested.
