Title: Employee Master Data (CRUD) - Create Employee
User Story: As an HR user, I want to create new employee records with all required fields so that employee data is accurately captured.
Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee data
  When I POST to /employees
  Then a new employee is created with a unique badgeId
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: badgeId must be unique.

Title: Employee Master Data (CRUD) - Read Employee
User Story: As an HR user, I want to view employee records with filtering and pagination so that I can efficiently manage large employee lists.
Acceptance Criteria:
Scenario: List employees
  Given multiple employees exist
  When I GET /employees with filters
  Then I receive a paginated, filtered list of employees
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Support filtering by department, status, etc.

Title: Employee Master Data (CRUD) - Update Employee
User Story: As an HR user, I want to update employee details so that records remain current.
Acceptance Criteria:
Scenario: Update employee
  Given an existing employee
  When I PATCH /employees/{id} with valid changes
  Then the employee record is updated
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: PATCH and PUT supported.

Title: Employee Master Data (CRUD) - Delete Employee
User Story: As an HR user, I want to soft-delete employee records so that historical data is preserved.
Acceptance Criteria:
Scenario: Soft-delete employee
  Given an existing employee
  When I DELETE /employees/{id}
  Then the employee is marked as deleted but not removed from the database
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Soft-delete only.
