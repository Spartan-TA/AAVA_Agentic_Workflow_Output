Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD APIs so that there is a single source of truth for all warehouse employee data.

Acceptance Criteria:
Scenario: Employee record management
Given I have HR manager access
When I create, update, retrieve, or delete employee records
Then each operation is available via POST/GET/PUT/PATCH/DELETE /employees, badgeId is unique, soft-delete is supported, pagination and filtering are available, and OpenAPI schemas include examples.

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Ensure badgeId uniqueness and support for soft-delete and pagination.
