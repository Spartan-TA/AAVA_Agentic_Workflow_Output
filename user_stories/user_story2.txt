Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD APIs so that we have a single source of truth for warehouse staff information.

Acceptance Criteria:
Scenario: Create Employee
Given I have valid employee data
When I POST to /employees
Then a new employee record is created and badgeId is unique

Scenario: Update Employee
Given an employee exists
When I PUT/PATCH to /employees/{id}
Then the employee record is updated

Scenario: Delete Employee
Given an employee exists
When I DELETE /employees/{id}
Then the employee is soft-deleted and not returned in active lists

Scenario: Pagination and Filtering
Given multiple employees exist
When I GET /employees with filters and pagination
Then only matching employees are returned with correct page size

Scenario: API Documentation
Given the API is available
When I view OpenAPI schemas
Then all endpoints and examples are documented

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Ensure badgeId uniqueness and support for soft-delete.
