Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD operations so that I can maintain an accurate and up-to-date employee master database.

Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee details
  When I POST to /employees
  Then the employee is created with a unique badgeId

Scenario: Update employee
  Given an existing employee
  When I PUT/PATCH to /employees/{id}
  Then the employee record is updated

Scenario: Delete employee
  Given an existing employee
  When I DELETE /employees/{id}
  Then the employee is soft-deleted and not returned in default queries

Scenario: List and filter employees
  Given multiple employees exist
  When I GET /employees with filters
  Then I receive paginated and filtered results

Scenario: OpenAPI documentation
  Given the API is running
  When I access the OpenAPI docs
  Then all endpoints and schemas are documented with examples

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Enforce unique badgeId, support soft-delete, and provide pagination/filtering.
