Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records (create, read, update, delete) so that there is a single source of truth for warehouse employee data.

Acceptance Criteria:

Scenario: Create employee
Given I have valid employee details
When I submit a POST request to /employees
Then a new employee is created with a unique badgeId

Scenario: Update employee
Given an existing employee
When I send a PUT or PATCH request with updated details
Then the employee record is updated accordingly

Scenario: Delete employee
Given an existing employee
When I send a DELETE request
Then the employee is soft-deleted and not returned in active queries

Scenario: List and filter employees
Given multiple employee records
When I request a paginated list with filters
Then only matching employees are returned

Scenario: OpenAPI documentation
Given the API is running
When I access the OpenAPI docs
Then all endpoints and schemas are documented with examples

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Enforce unique badgeId and support soft-delete.
