Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to create, read, update, and delete employee records with key attributes so that there is a single source of truth for warehouse employee data across all systems.

Acceptance Criteria:
Scenario: CRUD operations for employees
  Given I have access to the employee management module
  When I perform POST, GET, PUT, PATCH, or DELETE on /employees
  Then the employee data should be created, retrieved, updated, or soft-deleted as requested

Scenario: Unique badge ID enforcement
  Given I am creating or updating an employee
  When I enter a badgeId
  Then the system should enforce uniqueness and return an error if the badgeId already exists

Scenario: Pagination and filtering
  Given there are multiple employee records
  When I request a list with pagination and filters
  Then I should receive the correct subset of employees

Scenario: OpenAPI documentation
  Given I access the API documentation
  When I view the employee endpoints
  Then the schemas and examples should be present for all CRUD operations

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Support soft-delete, ensure all endpoints are documented, and badgeId is unique.
