Title: Employee CRUD - Create Employee Record
User Story: As an HR manager, I want to create new employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centralized.
Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee data
  When I POST to /employees
  Then a new employee is created with a unique badgeId

Scenario: BadgeId uniqueness
  Given an employee with badgeId exists
  When I try to create another with the same badgeId
  Then the request is rejected

Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Enforces data integrity

Title: Employee CRUD - Update and Soft Delete Employee
User Story: As an HR manager, I want to update or soft-delete employee records so that changes and terminations are accurately reflected without losing history.
Acceptance Criteria:
Scenario: Update employee
  Given an existing employee
  When I PUT or PATCH to /employees/{id}
  Then the employee record is updated

Scenario: Soft delete employee
  Given an active employee
  When I DELETE /employees/{id}
  Then the employee is marked as inactive, not removed

Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Soft delete preserves audit trail

Title: Employee CRUD - List and Filter Employees
User Story: As a supervisor, I want to list, paginate, and filter employees so that I can quickly find relevant staff.
Acceptance Criteria:
Scenario: List employees
  Given employees exist
  When I GET /employees
  Then I receive a paginated list

Scenario: Filter employees
  Given employees have various attributes
  When I filter by department or status
  Then only matching employees are returned

Priority: High
