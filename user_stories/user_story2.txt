Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD operations so that I have a single source of truth for all warehouse staff.

Acceptance Criteria:
Scenario: Create employee record
Given I have valid employee details
When I submit a POST request to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update employee record
Given an employee exists
When I send a PUT/PATCH request with updated details
Then the employee record is updated accordingly

Scenario: Delete employee record
Given an employee exists
When I send a DELETE request
Then the employee is soft-deleted and excluded from active lists

Scenario: List and filter employees
Given multiple employees exist
When I send a GET request with pagination and filters
Then I receive a filtered, paginated list of employees

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Ensure OpenAPI schemas are documented and badgeId uniqueness is enforced.
