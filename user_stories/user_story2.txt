Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD APIs so that there is a single source of truth for warehouse employee data

Acceptance Criteria:

Scenario: Create employee
Given I have valid employee details
When I POST to /employees
Then the employee is created with a unique badgeId

Scenario: Update employee
Given an existing employee
When I PUT or PATCH to /employees/{id}
Then the employee record is updated

Scenario: Delete employee
Given an existing employee
When I DELETE /employees/{id}
Then the employee is soft-deleted and not returned in active queries

Scenario: List employees
Given multiple employees exist
When I GET /employees with pagination and filters
Then I receive a paginated, filtered list

Scenario: OpenAPI documentation
Given I am a developer
When I view the API docs
Then I see schemas and examples for all endpoints

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: badgeId must be unique; support for soft-delete and filtering is required; ensure OpenAPI docs are up-to-date.
