Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records (create, read, update, delete) so that there is a single source of truth for all warehouse employee data.

Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee details
  When I POST to /employees
  Then a new employee is created with a unique badgeId

Scenario: Update employee
  Given an existing employee
  When I PUT or PATCH to /employees/{id}
  Then the employee record is updated

Scenario: Delete employee (soft-delete)
  Given an employee exists
  When I DELETE /employees/{id}
  Then the employee is soft-deleted and not returned in default queries

Scenario: List and filter employees
  Given multiple employees exist
  When I GET /employees with filters or pagination
  Then the correct subset of employees is returned

Scenario: OpenAPI documentation
  Given the API is running
  When I view the OpenAPI docs
  Then all employee endpoints and schemas are documented with examples

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Enforce unique badgeId; support pagination and filtering; support soft-delete.
