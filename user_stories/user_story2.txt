Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to create, read, update, and delete employee records So that I can maintain a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Create Employee
Given valid employee details
When I POST to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update Employee
Given an existing employee
When I PUT or PATCH to /employees/{id}
Then the employee record is updated

Scenario: Delete Employee
Given an existing employee
When I DELETE /employees/{id}
Then the employee is soft-deleted and not shown in active lists

Scenario: List Employees
Given multiple employee records
When I GET /employees with pagination and filtering
Then I receive a paginated, filtered list

Scenario: OpenAPI Documentation
Given the API is available
When I view the OpenAPI schema
Then I see examples for each endpoint

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Enforce unique badgeId, support soft-delete, ensure DTOs are mapped correctly.
