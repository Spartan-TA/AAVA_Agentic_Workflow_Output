Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records (create, read, update, delete) so that the warehouse has a single source of truth for employee information.

Acceptance Criteria:
Scenario: Create employee record
  Given I have valid employee details
  When I submit a POST request to /employees
  Then a new employee record is created with a unique badgeId

Scenario: Update employee record
  Given an existing employee
  When I send a PUT or PATCH request with updated details
  Then the employee record is updated accordingly

Scenario: Delete employee record
  Given an active employee
  When I send a DELETE request
  Then the employee record is soft-deleted and excluded from active lists

Scenario: Retrieve employee records
  Given multiple employees exist
  When I send a GET request to /employees with filters and pagination
  Then I receive a filtered, paginated list of employees

Scenario: OpenAPI documentation
  Given the API is available
  When I view the OpenAPI schema
  Then all endpoints and DTOs are documented with examples

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding (E01)
- Notes: Ensure badgeId uniqueness and support for soft-delete.
