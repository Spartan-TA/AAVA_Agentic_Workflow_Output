Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to manage employee records with CRUD operations so that I can maintain a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Manage employee records
  Given I have access to the employee management module
  When I create, retrieve, update, patch, or delete an employee
  Then the system should enforce unique badgeId, support soft-delete, and allow pagination and filtering
  And OpenAPI schemas with examples should be available

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup (E01)
- Notes: Ensure all CRUD endpoints are covered and badgeId uniqueness is validated.
