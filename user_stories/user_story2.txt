Title: Create Employee Domain Model

User Story:
As an HR administrator, I want to create, read, update, and delete employee records with fields like name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is managed centrally.

Acceptance Criteria:
Scenario 1: Create employee
  Given I have valid employee data
  When I POST to /employees
  Then a new employee is created with a unique badgeId

Scenario 2: Update employee
  Given an employee exists
  When I PUT or PATCH to /employees/{id} with updated data
  Then the employee record is updated

Scenario 3: Delete employee (soft delete)
  Given an employee exists
  When I DELETE /employees/{id}
  Then the employee status is set to inactive (soft delete)

Scenario 4: List and filter employees
  Given multiple employees exist
  When I GET /employees with pagination and filters
  Then I receive a paginated, filtered list

Scenario 5: OpenAPI documentation
  Given the API is running
  When I access the OpenAPI docs
  Then /employees endpoints are documented with examples

Additional Details:
Priority: High
Story Points: 8
Dependencies: E01
Notes: badgeId must be unique; support soft-delete.
