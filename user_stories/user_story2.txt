### E02 â Employee Master Data (CRUD)

**User Story 1: Create Employee API**
- **User Story:** As an HR user, I want to create employee records so that new hires are tracked in the system.
- **Acceptance Criteria:**
  - Given valid employee data,
  - When I POST to /employees,
  - Then a new employee is created with a unique badgeId.
- **Additional Details:** Priority: High; Story Points: 2; Dependencies: E01; Notes: Validate required fields.

**User Story 2: Retrieve Employee List**
- **User Story:** As an HR user, I want to list employees with filters so that I can find records efficiently.
- **Acceptance Criteria:**
  - Given employees exist,
  - When I GET /employees with filters,
  - Then I see paginated, filtered results.
- **Additional Details:** Priority: High; Story Points: 2; Dependencies: E02-1; Notes: Support department, status filters.

**User Story 3: Update Employee Details**
- **User Story:** As an HR user, I want to update employee details so that records remain current.
- **Acceptance Criteria:**
  - Given an employee exists,
  - When I PATCH/PUT to /employees/{id},
  - Then the employee's details are updated.
- **Additional Details:** Priority: High; Story Points: 2; Dependencies: E02-1; Notes: Only allowed fields editable.

**User Story 4: Soft Delete Employee**
- **User Story:** As an HR user, I want to soft-delete employees so that terminated staff are not lost but excluded from active lists.
- **Acceptance Criteria:**
  - Given an employee exists,
  - When I DELETE /employees/{id},
  - Then the employee is marked inactive, not removed from DB.
- **Additional Details:** Priority: High; Story Points: 1; Dependencies: E02-1; Notes: Soft delete only.

**User Story 5: OpenAPI Documentation**
- **User Story:** As a developer, I want OpenAPI docs with examples for employee APIs so that integration is easy.
- **Acceptance Criteria:**
  - Given the API is deployed,
  - When I access /swagger-ui,
  - Then I see all employee endpoints with request/response examples.
- **Additional Details:** Priority: High; Story Points: 1; Dependencies: E02-1; Notes: Keep docs up to date.
