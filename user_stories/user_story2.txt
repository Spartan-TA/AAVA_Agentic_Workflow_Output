Title: Employee CRUD API - Create Employee

User Story: As an HR user I want to create a new employee record with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee onboarding is tracked.

Acceptance Criteria:
Scenario: Create employee with valid data
Given I am authenticated as HR
When I POST to /employees with valid data
Then a new employee is created and returned with a unique badgeId

Scenario: Duplicate badgeId is rejected
Given an employee with badgeId X exists
When I POST to /employees with badgeId X
Then the request is rejected with a validation error

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique.

Title: Employee CRUD API - Read Employee(s)

User Story: As an HR user I want to retrieve employee records with pagination and filtering so that I can view and manage employee data efficiently.

Acceptance Criteria:
Scenario: Get all employees paginated
Given there are multiple employees
When I GET /employees?page=1&size=10
Then I receive a paginated list of employees

Scenario: Filter employees by department
Given employees exist in multiple departments
When I GET /employees?department=Shipping
Then only employees in Shipping are returned

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Filtering by multiple fields supported.

Title: Employee CRUD API - Update Employee

User Story: As an HR user I want to update employee details so that records remain accurate.

Acceptance Criteria:
Scenario: Update employee status
Given an employee exists
When I PATCH /employees/{id} with a new status
Then the employee's status is updated

Scenario: Update with invalid badgeId is rejected
Given an employee exists
When I PATCH /employees/{id} with a duplicate badgeId
Then the request is rejected

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Supports PATCH and PUT.

---

Title: Employee CRUD API - Delete (Soft Delete) Employee

User Story: As an HR user I want to soft-delete employee records so that historical data is preserved.

Acceptance Criteria:
Scenario: Soft-delete employee
Given an employee exists
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database

Scenario: Deleted employees are excluded from default queries
Given an employee is soft-deleted
When I GET /employees
Then the deleted employee is not returned

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Soft-delete flag is used.
