---
Epic: E02 - Employee Master Data (CRUD)

User Story 1: Employee Creation
Title: Create Employee Record
User Story: As an HR manager, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centralized.
Acceptance Criteria (Gherkin):
Given I have valid employee data,
When I POST to /employees,
Then a new employee record is created with a unique badgeId.
And the response includes the employee DTO.
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Supports onboarding.

User Story 2: Employee Retrieval
Title: Retrieve Employee Records
User Story: As an HR manager, I want to retrieve employee records with pagination and filtering so that I can efficiently manage large datasets.
Acceptance Criteria (Gherkin):
Given employees exist,
When I GET /employees with filters,
Then the response contains filtered employee records paginated.
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Supports reporting.

User Story 3: Employee Update
Title: Update Employee Record
User Story: As an HR manager, I want to update employee details so that records remain accurate.
Acceptance Criteria (Gherkin):
Given an employee exists,
When I PUT/PATCH to /employees/{id},
Then the employee record is updated.
And badgeId uniqueness is enforced.
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Supports lifecycle changes.

User Story 4: Employee Deletion
Title: Soft-Delete Employee Record
User Story: As an HR manager, I want to soft-delete employee records so that historical data is preserved.
Acceptance Criteria (Gherkin):
Given an employee exists,
When I DELETE /employees/{id},
Then the employee status is set to 'inactive' and not removed from DB.
Additional Details:
Priority: High
Story Points: 1
Dependencies: E01
Notes: Compliance requirement.

User Story 5: OpenAPI Documentation
Title: Document Employee APIs
User Story: As a developer, I want OpenAPI schemas with examples for employee endpoints so that integration is easier.
Acceptance Criteria (Gherkin):
Given the API is deployed,
When I access /swagger-ui,
Then employee endpoints are documented with request/response examples.
Additional Details:
Priority: High
Story Points: 1
Dependencies: E01
Notes: Supports integrations.
