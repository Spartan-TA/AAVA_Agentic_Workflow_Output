Title: Employee Master Data (CRUD)
User Story 1: As an HR user I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status So that I maintain accurate employee data
Acceptance Criteria:
Scenario: Employee creation
Given I am authenticated as HR
When I POST to /employees with valid data
Then a new employee is created and badgeId is unique
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Project scaffolding
- Notes: Validate badgeId uniqueness

User Story 2: As an HR user I want to update employee records So that I can keep information current
Acceptance Criteria:
Scenario: Employee update
Given an employee exists
When I PUT/PATCH to /employees/{id}
Then the record is updated and changes reflected
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Employee creation
- Notes: Support partial updates

User Story 3: As an HR user I want to soft-delete employee records So that historical data is preserved
Acceptance Criteria:
Scenario: Employee soft-delete
Given an employee exists
When I DELETE /employees/{id}
Then the employee is marked inactive but not removed from DB
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Employee creation
- Notes: Exclude inactive from active lists

User Story 4: As a supervisor I want to list employees with pagination and filtering So that I can find relevant records quickly
Acceptance Criteria:
Scenario: Employee listing
Given employees exist
When I GET /employees with filters
Then I receive paginated, filtered results
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Employee creation
- Notes: Support filter by department, status

User Story 5: As a developer I want OpenAPI schemas with examples for employee APIs So that integration is easier
Acceptance Criteria:
Scenario: API documentation
Given employee APIs are implemented
When I view OpenAPI docs
Then schemas and example payloads are present
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: Employee CRUD endpoints
- Notes: Keep docs updated
