Title: Employee Master Data (CRUD)
User Story: As an HR manager I want to manage employee records (create, view, update, delete) so that we have a single source of truth for all warehouse employees.
Acceptance Criteria:
Scenario: Employee CRUD operations
Given I am authenticated as HR
When I use the employee API endpoints
Then I can create, retrieve, update, patch, and soft-delete employee records
And badgeId is unique
And pagination and filtering are available
And OpenAPI schemas include examples
Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Soft-delete must not remove records from DB; ensure badgeId uniqueness.
