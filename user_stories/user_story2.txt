Title: Employee Master Data (CRUD)

User Story: As an HR manager I want to create, update, and manage employee records with unique badge IDs so that we maintain a single source of truth for warehouse employee data.

Acceptance Criteria:
Scenario: Employee CRUD Operations
Given the employee management API is available
When I POST, GET, PUT, PATCH, or DELETE employee records
Then unique badgeId is enforced, soft-delete is supported, pagination and filtering are available, and OpenAPI schemas include examples.

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding & Domain Setup
- Notes: Ensure badgeId uniqueness and soft-delete logic; provide API documentation with examples.
