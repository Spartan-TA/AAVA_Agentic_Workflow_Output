### E08 - Safety Incidents & OSHA Reporting

**User Story 1: Record Safety Incident**
- Title: Safety Incident Submission
- User Story: As a supervisor, I want to record safety incidents with severity, location, and involved employees so that incidents are tracked.
- Acceptance Criteria:
  - Given incident data, When I POST to /safety/incidents, Then the incident is validated and stored.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E02, E03, Notes: Validation required.

**User Story 2: Incident Investigation Workflow**
- Title: Manage Incident Status Workflow
- User Story: As a safety officer, I want to progress incidents through Open, Investigating, and Resolved statuses so that investigations are tracked.
- Acceptance Criteria:
  - Given an incident, When I update status, Then the workflow progresses accordingly.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Status transitions.

**User Story 3: OSHA Report Export**
- Title: Export OSHA 300/300A Reports
- User Story: As a compliance officer, I want to export OSHA summary reports so that regulatory requirements are met.
- Acceptance Criteria:
  - Given incident data, When I export, Then OSHA 300/300A fields are included.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: CSV/PDF format.

**User Story 4: Safety Metrics Dashboard**
- Title: Safety Metrics Dashboard
- User Story: As a manager, I want to view safety KPIs on a dashboard so that I can monitor trends.
- Acceptance Criteria:
  - Given incident data, When I access the dashboard, Then metrics are displayed and filterable.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Metrics endpoint.
