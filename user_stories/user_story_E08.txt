### E08 - Safety Incidents & OSHA Reporting

**User Story 1**
Title: Record Safety Incidents
User Story: As a supervisor, I want to record incidents and near-misses so that safety issues are tracked.
Acceptance Criteria:
Scenario: Incident recording
Given an incident
When I POST to /safety/incidents
Then the incident is stored with all required fields
Priority: High
Story Points: 3
Dependencies: E02, E03
Notes: Validate severity, location, and involved employees.

**User Story 2**
Title: Manage Incident Workflow
User Story: As a safety officer, I want to update incident status through investigation and resolution so that corrective actions are tracked.
Acceptance Criteria:
Scenario: Status workflow
Given an open incident
When I update the status
Then the workflow transitions through Open, Investigating, Resolved
Priority: High
Story Points: 2
Dependencies: E02, E03
Notes: Track timestamps and actors for each status.

**User Story 3**
Title: Export OSHA Summary Reports
User Story: As a compliance officer, I want to export OSHA 300/300A summaries so that regulatory requirements are met.
Acceptance Criteria:
Scenario: OSHA export
Given incident records
When I export OSHA summaries
Then the file contains all required OSHA fields
Priority: High
Story Points: 2
Dependencies: E02, E03
Notes: Support CSV and PDF formats.

**User Story 4**
Title: Safety Metrics Dashboard
User Story: As a manager, I want a dashboard of safety KPIs so that I can monitor trends and compliance.
Acceptance Criteria:
Scenario: Metrics dashboard
Given incident data
When I access the dashboard
Then I see metrics such as incident rate, days since last incident, and open investigations
Priority: High
Story Points: 2
Dependencies: E02, E03
Notes: Dashboard endpoints for BI integration.
