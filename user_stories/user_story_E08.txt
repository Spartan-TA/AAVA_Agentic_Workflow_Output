### E08 - Safety Incidents & OSHA Reporting

**User Story 1**
- Title: Record Safety Incidents and Near-Misses
- User Story: As a safety officer, I want to record incidents and near-misses with severity, location, description, and involved employees so that safety data is tracked.
- Acceptance Criteria:
  - Given the incident API is available,
    When I submit an incident,
    Then all required fields are validated and stored.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Safety tracking.

**User Story 3**
- Title: Export OSHA Summary Reports
- User Story: As a compliance officer, I want to export OSHA 300/300A fields so that regulatory reporting is simplified.
- Acceptance Criteria:
  - Given incident data exists,
    When I request an export,
    Then OSHA fields are included in the report.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Regulatory compliance.

**User Story 4**
- Title: Metrics Dashboard for Safety KPIs
- User Story: As a manager, I want dashboard endpoints for safety metrics so that trends are visible.
- Acceptance Criteria:
  - Given incidents are recorded,
    When I access the dashboard,
    Then KPIs (incident rate, severity, resolution time) are displayed.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E02, E03, Notes: Analytics.
