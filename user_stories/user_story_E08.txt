### E08: Safety Incidents & OSHA Reporting

**User Story 1: Record Safety Incident**
- User Story: As a supervisor, I want to record safety incidents with severity, location, and involved employees So that incidents are tracked for compliance.
- Acceptance Criteria:
  - Scenario: Incident creation
    - Given incident details
    - When I POST to /safety/incidents
    - Then the incident is recorded with status Open
  - Scenario: Validation
    - Given incomplete data
    - When I submit the form
    - Then the system returns a validation error
- Priority: High
- Story Points: 3
- Dependencies: E02, E03
- Notes: Near-misses included.

**User Story 2: Incident Investigation Workflow**
- User Story: As a safety officer, I want to manage incident investigation and corrective actions So that incidents are resolved and reported.
- Acceptance Criteria:
  - Scenario: Investigation status
    - Given an open incident
    - When I update the status
    - Then the workflow moves to Investigating or Resolved
  - Scenario: OSHA report export
    - Given resolved incidents
    - When I export OSHA summary
    - Then the file contains all required OSHA 300/300A fields
- Priority: High
- Story Points: 5
- Dependencies: E02, E03
- Notes: Metrics dashboard endpoints required.
