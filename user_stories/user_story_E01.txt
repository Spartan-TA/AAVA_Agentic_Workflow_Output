### E01: Project Scaffolding & Domain Setup

**User Story 1: Initialize Spring Boot Project Structure**
- User Story: As a developer, I want a standardized Spring Boot project structure with base packages So that all modules follow consistent conventions.
- Acceptance Criteria:
  - Scenario: Project initialization
    - Given a new project repository
    - When I clone and build the project
    - Then the project builds successfully and runs on port 8080
  - Scenario: Base package verification
    - Given the project source
    - When I inspect the codebase
    - Then I see base packages for employee, scheduling, attendance, and safety modules
- Priority: High
- Story Points: 3
- Dependencies: None
- Notes: README must include build/run instructions.

**User Story 2: Database Migration Setup**
- User Story: As a developer, I want Flyway or Liquibase configured for DB migrations So that database changes are versioned and repeatable.
- Acceptance Criteria:
  - Scenario: Migration runs on startup
    - Given a fresh database
    - When I start the application
    - Then baseline migration is applied without errors
  - Scenario: Migration verification
    - Given the project
    - When I check the migration history
    - Then all migrations are tracked and versioned
- Priority: High
- Story Points: 2
- Dependencies: None
- Notes: Must support both H2 and Postgres.

**User Story 3: Actuator Health Endpoint**
- User Story: As an operator, I want an Actuator health endpoint enabled So that I can monitor application health.
- Acceptance Criteria:
  - Scenario: Health endpoint returns UP
    - Given the application is running
    - When I call /actuator/health
    - Then the response is status UP
- Priority: High
- Story Points: 1
- Dependencies: None
- Notes: Health endpoint must be documented in README.
