### E01: Project Scaffolding & Domain Setup

**User Story 1**
Title: Initialize Spring Boot Project Structure
User Story: As a DEVELOPER I want a standardized Spring Boot project structure So that all modules follow consistent conventions
Acceptance Criteria:
Scenario: Project builds and runs
Given the project is cloned
When I run `mvn clean install` and `java -jar target/app.jar`
Then the application starts on port 8080 and the health endpoint returns UP
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: None
- Notes: README must include build/run steps

**User Story 2**
Title: Configure Database Migration Tool
User Story: As a DEVELOPER I want Flyway/Liquibase configured So that database schema changes are versioned and repeatable
Acceptance Criteria:
Scenario: Baseline migration runs
Given a clean database
When the application starts
Then Flyway/Liquibase applies the baseline migration and the schema is created
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Migration scripts must be idempotent

**User Story 3**
Title: Enable Actuator Health Endpoints
User Story: As a DEVOPS ENGINEER I want Actuator endpoints enabled So that I can monitor application health
Acceptance Criteria:
Scenario: Health endpoint returns status
Given the application is running
When I access `/actuator/health`
Then I receive a JSON response with status UP
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Only health endpoint exposed by default

**User Story 4**
Title: Establish Base Package Structure
User Story: As a DEVELOPER I want core modules (employee, scheduling, attendance, safety) structured in base packages So that code is organized and maintainable
Acceptance Criteria:
Scenario: Packages exist and are empty
Given the project is generated
When I browse the source tree
Then I see base packages for each core module
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Follows company package naming conventions
