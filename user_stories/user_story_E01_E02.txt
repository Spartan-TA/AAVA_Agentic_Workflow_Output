------------------------------------------------------------
Epic E01: Project Scaffolding & Domain Setup
------------------------------------------------------------

User Story 1: Initialize Spring Boot Project

Title: Initialize Spring Boot Project
User Story: As a developer, I want to initialize a Spring Boot project with Maven so that the codebase is standardized and easy to maintain.
Acceptance Criteria:
  Scenario: Project builds and runs
    Given the project repository is cloned
    When I run 'mvn clean install' and 'java -jar target/app.jar'
    Then the application starts successfully on port 8080

  Scenario: Actuator health endpoint is available
    Given the application is running
    When I access '/actuator/health'
    Then the endpoint returns status UP

Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: None
  Notes: Foundation for all modules

---

User Story 2: Configure Base Packages and Modules

Title: Configure Base Packages and Modules
User Story: As a developer, I want to set up base packages and core modules (employee, scheduling, attendance, safety) so that the architecture is modular and scalable.
Acceptance Criteria:
  Scenario: Base package structure exists
    Given the project is initialized
    When I inspect the source code
    Then packages for employee, scheduling, attendance, and safety are present

  Scenario: Modules are registered
    Given the application is running
    When I check the logs
    Then each module is loaded without errors

Additional Details:
  Priority: High
  Story Points: 3
  Dependencies: User Story 1
  Notes: Enables separation of concerns

------------------------------------------------------------
Epic E02: Employee Master Data (CRUD)
------------------------------------------------------------

User Story 1: Create Employee Record

Title: Create Employee Record
User Story: As an HR user, I want to create a new employee record with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is maintained centrally.
Acceptance Criteria:
  Scenario: Valid employee creation
    Given I have valid employee details
    When I POST to /employees
    Then a new employee is created with a unique badgeId

  Scenario: Duplicate badgeId is rejected
    Given an employee with badgeId exists
    When I try to create another with same badgeId
    Then the request is rejected with an error

Additional Details:
  Priority: High
  Story Points: 3
  Dependencies: E01
  Notes: Ensures uniqueness

---

User Story 2: Update Employee Record

Title: Update Employee Record
User Story: As an HR user, I want to update employee details so that changes in status, department, or role are reflected accurately.
Acceptance Criteria:
  Scenario: Update employee details
    Given an employee exists
    When I PUT/PATCH to /employees/{id}
    Then the employee record is updated

  Scenario: Invalid update is rejected
    Given invalid data
    When I attempt to update
    Then the request fails with validation errors

Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: User Story 1
  Notes: Supports lifecycle changes

---

User Story 3: Delete Employee Record (Soft Delete)

Title: Delete Employee Record (Soft Delete)
User Story: As an HR user, I want to soft-delete employee records so that historical data is preserved but inactive employees are hidden.
Acceptance Criteria:
  Scenario: Soft delete employee
    Given an employee exists
    When I DELETE /employees/{id}
    Then the employee is marked as inactive but not removed from DB

  Scenario: Deleted employees are excluded from active lists
    Given employees are soft-deleted
    When I GET /employees?status=active
    Then only active employees are returned

Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: User Story 1
  Notes: Compliance with retention

---

User Story 4: Retrieve Employee List with Filtering

Title: Retrieve Employee List with Filtering
User Story: As an HR user, I want to retrieve a paginated and filtered list of employees so that I can quickly find relevant records.
Acceptance Criteria:
  Scenario: Paginated list
    Given employees exist
    When I GET /employees?page=1&size=20
    Then 20 employees are returned

  Scenario: Filter by department
    Given employees in multiple departments
    When I filter by department
    Then only employees from that department are listed

Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: User Story 1
  Notes: Supports large datasets
