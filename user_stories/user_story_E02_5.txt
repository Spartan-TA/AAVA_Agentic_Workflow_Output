Title: E02-5 OpenAPI Documentation for Employee APIs

User Story:
As a developer or integrator,
I want comprehensive OpenAPI documentation for all employee-related APIs,
So that I can understand, test, and integrate with the endpoints efficiently and accurately.

Acceptance Criteria:
Given all employee API endpoints (create, retrieve, update, delete),
When the OpenAPI spec is generated,
Then all endpoints, request/response schemas, parameters, authentication requirements, and error codes are documented.

Given a change to any employee API endpoint,
When the change is merged to main,
Then the OpenAPI spec is updated to reflect the latest contract.

Given a request for documentation,
When the documentation endpoint is accessed,
Then the latest OpenAPI spec is available in both JSON and interactive UI formats (e.g., Swagger UI).

Additional Details:
- Documentation must be versioned and accessible to authorized users.
- Example requests and responses must be included.
- Security and error handling must be clearly described.
- Documentation must be reviewed and approved before release.
