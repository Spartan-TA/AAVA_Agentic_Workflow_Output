Title: Audit Trail & Compliance - Log Sensitive Changes
User Story: As a compliance officer I want all sensitive changes to be logged with actor and timestamp So that forensic analysis is possible

Acceptance Criteria:
Scenario: Log create/update/delete
Given a sensitive action occurs
When the action is performed
Then an audit log entry is created with before/after values

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: RBAC
- Notes: Immutable log table

Title: Audit Trail & Compliance - Tamper-Evident Storage
User Story: As a compliance officer I want audit logs stored in tamper-evident format So that integrity is ensured

Acceptance Criteria:
Scenario: Tamper-evident log
Given logs are stored
When I review storage
Then logs cannot be altered without detection

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Audit logging
- Notes: Use cryptographic hash or append-only storage
