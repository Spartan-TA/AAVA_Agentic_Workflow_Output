EPIC E02: EMPLOYEE MASTER DATA (CRUD)

===========================================

Title: Employee CRUD - Create Employee
User Story: As an HR user, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that all employee data is centrally managed.
Acceptance Criteria:
Scenario: Create employee
  Given valid employee details
  When I POST to /employees
  Then the employee is created and badgeId is unique
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique.

---

Title: Employee CRUD - Update Employee
User Story: As an HR user, I want to update employee details so that records remain accurate over time.
Acceptance Criteria:
Scenario: Update employee
  Given an existing employee
  When I PUT/PATCH to /employees/{id}
  Then the employee details are updated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Validate badgeId uniqueness on update.

---

Title: Employee CRUD - Delete (Soft Delete) Employee
User Story: As an HR user, I want to soft-delete employees so that historical data is preserved but inactive employees are hidden.
Acceptance Criteria:
Scenario: Soft delete employee
  Given an active employee
  When I DELETE /employees/{id}
  Then the employee status is set to inactive and not returned in active queries
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: No hard deletes.

---

Title: Employee CRUD - List & Filter Employees
User Story: As an HR user, I want to list, paginate, and filter employees so that I can quickly find relevant records.
Acceptance Criteria:
Scenario: List and filter employees
  Given multiple employees
  When I GET /employees with filters
  Then the results are paginated and filtered as requested
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Support filtering by department, status, etc.

---

Title: Employee CRUD - OpenAPI Documentation
User Story: As a developer, I want OpenAPI schemas with examples for employee APIs so that integration is straightforward.
Acceptance Criteria:
Scenario: OpenAPI docs available
  Given the API is running
  When I access /v3/api-docs
  Then employee endpoints are documented with request/response examples
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Keep docs up to date.
