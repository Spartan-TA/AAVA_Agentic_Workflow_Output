EPIC E01: Project Scaffolding & Domain Setup
================================================================================

E01-1: Initialize Spring Boot Project
User Story: As a developer, I want to initialize a new Spring Boot project with 
Maven so that I have a standardized foundation for the application.
Acceptance Criteria:
  Given I am in the project root,
  When I run 'mvn clean install',
  Then the project builds successfully and runs on port 8080.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: None
  Notes: Base for all modules.

E01-2: Configure Base Package Structure
User Story: As a developer, I want to set up the base package structure for core 
modules so that code organization is consistent and maintainable.
Acceptance Criteria:
  Given the project is initialized,
  When I open the source directory,
  Then I see packages for employee, scheduling, attendance, and safety.
Additional Details:
  Priority: High | Story Points: 1 | Dependencies: E01-1
  Notes: Follows company standards.

E01-3: Add Database Migration Tooling
User Story: As a developer, I want to add Flyway or Liquibase for database 
migrations so that schema changes are versioned and repeatable.
Acceptance Criteria:
  Given the project is running,
  When I start the application,
  Then Flyway/Liquibase applies the baseline migration to the database.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E01-1
  Notes: Must be documented in README.

E01-4: Enable Actuator and Document Setup
User Story: As a developer, I want to enable Spring Boot Actuator and document 
build/run steps so that health checks and onboarding are easy.
Acceptance Criteria:
  Given the application is running,
  When I access /actuator/health,
  Then I receive a status of UP.
  And the README contains build and run instructions.
Additional Details:
  Priority: High | Story Points: 1 | Dependencies: E01-1
  Notes: Required for monitoring.

EPIC E02: Employee Master Data (CRUD)
================================================================================

E02-1: Create Employee Domain Model
User Story: As a developer, I want to define the Employee entity with fields 
(name, badgeId, role, department, shiftGroup, hireDate, status) so that employee 
data is structured.
Acceptance Criteria:
  Given the database schema is migrated,
  When I inspect the Employee table,
  Then all required fields are present.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E01
  Notes: Foundation for all employee features.

E02-2: Implement Employee CRUD APIs
User Story: As an HR user, I want to create, read, update, and delete employee 
records via REST APIs so that I can manage employee data.
Acceptance Criteria:
  Given valid employee data,
  When I call POST/GET/PUT/PATCH/DELETE /employees,
  Then the operations succeed and badgeId is unique.
Additional Details:
  Priority: High | Story Points: 3 | Dependencies: E02-1
  Notes: Supports pagination and filtering.

E02-3: Support Soft-Delete for Employees
User Story: As an HR user, I want to soft-delete employees so that historical 
data is retained for compliance.
Acceptance Criteria:
  Given an employee is soft-deleted,
  When I fetch employees,
  Then the deleted employee is excluded from active lists but present in audit logs.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E02-2
  Notes: Required for compliance.

E02-4: Document APIs with OpenAPI
User Story: As a developer, I want to document all employee APIs with OpenAPI 
schemas and examples so that integration is easy.
Acceptance Criteria:
  Given the API documentation endpoint,
  When I access /swagger-ui.html,
  Then all employee endpoints are described with request/response examples.
Additional Details:
  Priority: High | Story Points: 1 | Dependencies: E02-2
  Notes: Must be kept up to date.

EPIC E03: Role-Based Access Control (RBAC)
================================================================================

E03-1: Add Spring Security and Roles
User Story: As a system admin, I want to configure Spring Security with roles 
(ADMIN, HR, SUPERVISOR, WORKER) so that access is restricted appropriately.
Acceptance Criteria:
  Given a user with a specific role,
  When they access protected endpoints,
  Then permissions are enforced as per role.
Additional Details:
  Priority: High | Story Points: 3 | Dependencies: E01, E02
  Notes: Role matrix documented.

E03-2: Implement Method and Endpoint Security
User Story: As a developer, I want to secure methods and endpoints so that 
unauthorized access is prevented.
Acceptance Criteria:
  Given an unauthorized request,
  When it is made to a protected endpoint,
  Then a 401 or 403 is returned as appropriate.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E03-1
  Notes: Test coverage required.

E03-3: Add Row-Level Security Constraints
User Story: As a supervisor, I want to be limited to managing only my team's 
records so that data privacy is maintained.
Acceptance Criteria:
  Given a supervisor is logged in,
  When they access employee data,
  Then only their direct reports are visible/editable.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E03-2
  Notes: Applies to all sensitive modules.

E03-4: Support API Key/OAuth2 Toggle
User Story: As a system admin, I want to toggle between API key and OAuth2 
authentication via configuration so that integration flexibility is provided.
Acceptance Criteria:
  Given the security config is changed,
  When the app is restarted,
  Then the selected authentication method is enforced.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E03-1
  Notes: Document toggle steps.

EPIC E04: Time & Attendance (Clock In/Out)
================================================================================

E04-1: Implement Clock-In/Clock-Out Endpoints
User Story: As a worker, I want to clock in and out via API so that my attendance 
is accurately recorded.
Acceptance Criteria:
  Given a valid employee,
  When they POST to /attendance/clock-in or /clock-out,
  Then the event is recorded with timestamp and device info.
Additional Details:
  Priority: High | Story Points: 3 | Dependencies: E02, E03
  Notes: Geofence optional.

E04-2: Calculate Hours Worked Per Shift
User Story: As a payroll admin, I want the system to calculate hours worked per 
shift so that payroll is accurate.
Acceptance Criteria:
  Given clock-in/out events,
  When daily totals are computed,
  Then hours worked are available per employee per shift.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E04-1
  Notes: Handles overnight shifts.

E04-3: Handle Missed Punches and Corrections
User Story: As a supervisor, I want to manage missed punches and corrections via 
approval workflow so that attendance data is correct.
Acceptance Criteria:
  Given a missed punch,
  When a correction is submitted,
  Then an approval task is created and processed.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E04-1
  Notes: Audit all corrections.

E04-4: Export Attendance Reports
User Story: As an HR user, I want to export attendance reports in CSV format so 
that I can analyze and share data.
Acceptance Criteria:
  Given attendance data,
  When I request an export,
  Then a CSV file is generated with all relevant fields.
Additional Details:
  Priority: High | Story Points: 1 | Dependencies: E04-2
  Notes: Export includes corrections.

EPIC E05: Shift & Schedule Management
================================================================================

E05-1: Create Shift Templates and Rotations
User Story: As a scheduler, I want to define recurring shift templates and 
rotations so that scheduling is efficient.
Acceptance Criteria:
  Given access to scheduling,
  When I create a template,
  Then it can be assigned to employees and reused.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E02, E03, E04
  Notes: Supports overtime rules.

E05-2: Assign Shifts to Employees
User Story: As a supervisor, I want to assign shifts to employees in bulk so that 
staffing is managed easily.
Acceptance Criteria:
  Given a list of employees,
  When I assign a shift,
  Then assignments are created and conflicts are detected/prevented.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E05-1
  Notes: Audit entries generated.

E05-3: Display Personal Upcoming Shifts
User Story: As a worker, I want to view my upcoming shifts so that I can plan my 
schedule.
Acceptance Criteria:
  Given I am logged in,
  When I access my schedule,
  Then all upcoming assigned shifts are displayed.
Additional Details:
  Priority: High | Story Points: 1 | Dependencies: E05-2
  Notes: Mobile-friendly.

E05-4: Handle Blackout Dates and Calendars
User Story: As a scheduler, I want to manage blackout dates and operation 
calendars so that shifts are not assigned during closures.
Acceptance Criteria:
  Given a blackout date,
  When I schedule shifts,
  Then the system prevents assignments on those dates.
Additional Details:
  Priority: High | Story Points: 2 | Dependencies: E05-1
  Notes: Calendar integration.
