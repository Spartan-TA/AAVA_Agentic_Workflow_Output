Title: Create Employee Domain Model

User Story: As a Developer I want to define the Employee entity with required fields So that employee data can be managed consistently

Acceptance Criteria:
Scenario: Employee entity defined
Given the project structure is ready
When I create the Employee class with name, badgeId, role, department, shiftGroup, hireDate, status
Then the entity should be available for CRUD operations

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Project scaffolding (E01)
- Notes: Use JPA annotations

Title: Implement Employee CRUD APIs

User Story: As an HR Manager I want to create, read, update, and delete employee records So that employee information is kept up to date

Acceptance Criteria:
Scenario: Create employee
Given valid employee data
When I submit a create request
Then a new employee record should be created

Scenario: Update employee
Given an existing employee
When I submit an update request
Then the employee record should be updated

Scenario: Delete employee
Given an existing employee
When I submit a delete request
Then the employee record should be removed

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Employee domain model
- Notes: Validate input data
