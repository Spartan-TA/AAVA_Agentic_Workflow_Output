Title: Create Employee Domain and CRUD API

User Story: As an HR manager I want to manage employee records with create, read, update, and delete operations So that I can maintain accurate and up-to-date employee information

Acceptance Criteria:
Scenario: Create employee
  Given I have valid employee details
  When I POST to /employees
  Then a new employee record is created and returned
Scenario: Read employee
  Given employee records exist
  When I GET /employees/{id}
  Then the correct employee details are returned
Scenario: Update employee
  Given an employee exists
  When I PUT or PATCH to /employees/{id}
  Then the employee record is updated
Scenario: Delete employee
  Given an employee exists
  When I DELETE /employees/{id}
  Then the employee record is soft-deleted and excluded from active queries

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project scaffolding (E01)
- Notes: Ensure OpenAPI schemas are documented and badgeId is unique
