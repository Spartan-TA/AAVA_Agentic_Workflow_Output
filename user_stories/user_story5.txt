Title: Create Employee Domain Model

User Story:
As a backend developer,
I want to define the Employee domain model with fields such as name, badgeId, role, department, shiftGroup, hireDate, and status,
So that employee records are structured and ready for CRUD operations and integration.

Acceptance Criteria:
- Employee entity is defined with all required fields.
- badgeId is unique and enforced at the database level.
- Employee status supports values like Active, Terminated, On Leave.
- Entity is mapped to a database table with migrations.
- Unit tests cover model validation and constraints.

Additional Details:
- Use JPA annotations for entity mapping.
- Include audit fields (createdAt, updatedAt).
- Document the domain model in the codebase and API schemas.
