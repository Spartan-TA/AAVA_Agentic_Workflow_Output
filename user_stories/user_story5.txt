Title: Enforce Unique Badge ID and Employee List Filtering

User Story: As an HR manager I want the system to enforce unique badge IDs and support pagination/filtering on employee lists So that data integrity is maintained and large employee lists are manageable

Acceptance Criteria:
Scenario: Unique badgeId enforcement
Given an employee with badgeId X exists
When I attempt to create another employee with badgeId X
Then the API returns a validation error

Scenario: Employee list filtering
Given multiple employees exist
When I GET /employees with filter parameters (e.g., department, status)
Then only matching employees are returned, paginated

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Employee CRUD APIs (E02)
- Notes: Filtering and pagination must be documented in OpenAPI schemas
