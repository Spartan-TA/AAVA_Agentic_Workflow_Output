Title: Implement Employee Domain and CRUD APIs
User Story: As an HR manager I want to create, read, update, and delete employee records via APIs so that employee master data is managed efficiently and accurately
Acceptance Criteria:
Scenario: Employee CRUD operations
Given valid employee data
When I use the POST/GET/PUT/PATCH/DELETE endpoints on /employees
Then the employee records are created, retrieved, updated, and deleted as expected
Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project scaffolding
- Notes: Unique badgeId must be enforced; soft-delete should be supported; pagination and filtering required; OpenAPI schemas with examples.
