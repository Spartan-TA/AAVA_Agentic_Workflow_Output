### Epic E03: Role-Based Access Control (RBAC)

**User Story 1: Add Role Definitions and Assignment**
User Story: As an admin I want to define roles (ADMIN, HR, SUPERVISOR, WORKER) and assign them to users so that access is controlled.
Acceptance Criteria:
Scenario: Role assignment
Given a user account
When I assign a role
Then the user has permissions associated with that role
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Store roles in DB

**User Story 2: Implement Endpoint and Method Security**
User Story: As a developer I want to secure endpoints and methods based on user roles so that sensitive operations are restricted.
Acceptance Criteria:
Scenario: Unauthorized access
Given a user without required role
When they access a protected endpoint
Then the API returns 401 or 403
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02, E03
- Notes: Use Spring Security annotations

**User Story 3: Enforce Row-Level Security Constraints**
User Story: As a supervisor I want to access only my team's records so that privacy is maintained.
Acceptance Criteria:
Scenario: Row-level access
Given a supervisor user
When they query employee data
Then only records for their team are returned
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02, E03
- Notes: Implement team mapping

**User Story 4: Support API Key/OAuth2 Toggle**
User Story: As an admin I want to toggle between API key and OAuth2 authentication so that integration flexibility is provided.
Acceptance Criteria:
Scenario: Auth method toggle
Given the config is updated
When I restart the application
Then the selected authentication method is enforced
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Document config options

**User Story 5: Cover Security Rules with Automated Tests**
User Story: As a QA engineer I want automated tests for security rules so that vulnerabilities are detected early.
Acceptance Criteria:
Scenario: Security test coverage
Given security rules are defined
When I run the test suite
Then unauthorized and forbidden actions are tested and validated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Use test coverage tools
