### Epic E03: Role-Based Access Control (RBAC)

#### User Story 1: Implement Role-Based Endpoint Security
- **Title:** Endpoint Security by Role
- **User Story:** As an admin, I want endpoints secured by role so that only authorized users can access sensitive data.
- **Acceptance Criteria:**
  ```
  Scenario: Access control enforcement
    Given a user with HR role
    When they access /employees
    Then access is granted
    And when a WORKER accesses /employees
    Then access is forbidden (403)
  ```
- **Priority:** High
- **Story Points:** 3
- **Dependencies:** E01, E02
- **Notes:** Security rules covered by tests.

#### User Story 2: Row-Level Security for Supervisors
- **Title:** Supervisor Row-Level Access
- **User Story:** As a supervisor, I want to access only my team's records so that privacy is maintained.
- **Acceptance Criteria:**
  ```
  Scenario: Supervisor limited access
    Given a supervisor is logged in
    When they GET /employees
    Then only employees in their shiftGroup are returned
  ```
- **Priority:** High
- **Story Points:** 3
- **Dependencies:** E01, E02
- **Notes:** Row-level constraints enforced.

#### User Story 3: API Key/OAuth2 Toggle
- **Title:** Configurable Auth Mechanism
- **User Story:** As a system admin, I want to toggle between API key and OAuth2 authentication so that integration flexibility is supported.
- **Acceptance Criteria:**
  ```
  Scenario: Auth method toggle
    Given the config is set to OAuth2
    When a request is made
    Then OAuth2 is enforced
    And when config is set to API key
    Then API key is enforced
  ```
- **Priority:** High
- **Story Points:** 2
- **Dependencies:** E01, E02
- **Notes:** Configurable via application properties.

#### User Story 4: Unauthorized and Forbidden Response Handling
- **Title:** Proper 401/403 Responses
- **User Story:** As a user, I want unauthorized and forbidden actions to return correct HTTP status codes so that security is clear.
- **Acceptance Criteria:**
  ```
  Scenario: Unauthorized and forbidden responses
    Given a user is not authenticated
    When they access a protected endpoint
    Then response is 401
    And when authenticated but not authorized
    Then response is 403
  ```
- **Priority:** High
- **Story Points:** 1
- **Dependencies:** E01, E02
- **Notes:** Standardized error messages.
