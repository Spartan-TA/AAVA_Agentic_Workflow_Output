### EPIC E03 - Role Based Access Control (RBAC)

**User Story 1**
Title: Implement Role Definitions and Assignment

User Story: As an admin I want to define roles (ADMIN, HR, SUPERVISOR, WORKER) and assign them to users So that access can be controlled.

Acceptance Criteria:
Scenario: Role assignment
Given a user account
When I assign a role
Then the user has permissions associated with that role

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01,E02
- Notes: Roles stored in DB.

---

**User Story 2**
Title: Secure Endpoints by Role

User Story: As a developer I want to restrict API endpoints based on user roles So that sensitive operations are protected.

Acceptance Criteria:
Scenario: Endpoint security
Given a user with insufficient role
When they access a restricted endpoint
Then they receive a 403 Forbidden response

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E03
- Notes: Use method-level security annotations.

---

**User Story 3**
Title: Support API Key/OAuth2 Toggle via Config

User Story: As an ops engineer I want to toggle between API key and OAuth2 authentication So that integration flexibility is provided.

Acceptance Criteria:
Scenario: Auth method toggle
Given the config is set to API key
When I authenticate
Then API key is required
Given the config is set to OAuth2
When I authenticate
Then OAuth2 is required

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Document config options.

---

**User Story 4**
Title: Enforce Row-Level Security for Supervisors

User Story: As a supervisor I want to access only my team's records So that data privacy is maintained.

Acceptance Criteria:
Scenario: Row-level access
Given I am a supervisor
When I query employee data
Then I see only my team's records

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Map supervisor to team.

---

**User Story 5**
Title: Cover Security Rules with Automated Tests

User Story: As a QA engineer I want automated tests for security rules So that unauthorized access is prevented.

Acceptance Criteria:
Scenario: Security test coverage
Given the test suite
When I run security tests
Then unauthorized requests return 401 and forbidden actions return 403

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Include edge cases.
