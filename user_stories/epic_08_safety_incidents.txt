### E08: Safety Incidents & OSHA Reporting

**User Story 1**
- Title: Record Safety Incident
- User Story: As a supervisor, I want to record safety incidents and near-misses so that risks are documented.
- Acceptance Criteria in Gherkin format:
  Scenario: Submit incident report
  Given an incident occurs
  When I POST to /safety/incidents with required details
  Then the incident is recorded and status is set to Open
- Additional Details:
  * Priority: High
  * Story Points: 2
  * Dependencies: E02, E03
  * Notes: Validate severity, location, involved employees.

**User Story 2**
- Title: Incident Investigation Workflow
- User Story: As a safety manager, I want a workflow for investigating incidents so that corrective actions are tracked.
- Acceptance Criteria in Gherkin format:
  Scenario: Incident status workflow
  Given an incident is recorded
  When investigation starts and completes
  Then status transitions from Open to Investigating to Resolved
- Additional Details:
  * Priority: High
  * Story Points: 3
  * Dependencies: E02, E03
  * Notes: Track corrective actions.

**User Story 3**
- Title: OSHA Report Generation
- User Story: As a compliance officer, I want to generate OSHA summary reports so that regulatory requirements are met.
- Acceptance Criteria in Gherkin format:
  Scenario: Export OSHA 300/300A
  Given incident data exists
  When I request an OSHA report
  Then a file is generated with required fields
- Additional Details:
  * Priority: High
  * Story Points: 2
  * Dependencies: E02, E03
  * Notes: Metrics dashboard endpoints available.
