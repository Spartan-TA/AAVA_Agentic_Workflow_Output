Title: Audit Logging Pipeline for Sensitive Changes

User Story: As a compliance officer I want all create, update, and delete actions on sensitive data to be logged with actor, timestamp, and before/after values so that we can meet regulatory requirements

Acceptance Criteria:
Scenario: Logging a sensitive change
Given a user updates an employee's PII
When the change is saved
Then an audit log entry is created with all required details and stored immutably

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Audit log service, database
- Notes: Coverage must include employee, schedule, approval, and payroll changes
