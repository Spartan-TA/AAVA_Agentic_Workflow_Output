Title: Document Employee APIs with OpenAPI Schemas and Examples

User Story: As a Developer I want all employee-related APIs to be documented with OpenAPI schemas and examples So that integration and testing are consistent and reliable

Acceptance Criteria:

Scenario: OpenAPI schema for employee endpoints
Given the API documentation is generated
When I view the /employees endpoints
Then I should see request and response schemas for all CRUD operations

Scenario: Example payloads
Given the OpenAPI docs are available
When I review the documentation
Then I should see example request and response bodies for each endpoint

Scenario: Schema updates
Given the employee model changes
When I update the API
Then the OpenAPI documentation is updated accordingly

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Use OpenAPI 3.0+; ensure all fields (name, badgeId, role, department, shiftGroup, hireDate, status) are documented.
