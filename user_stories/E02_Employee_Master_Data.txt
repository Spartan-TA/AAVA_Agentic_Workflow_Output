EPIC E02: Employee Master Data (CRUD)

---

Title: Employee Master Data - Create Employee
User Story: As an HR I want to create new employee records with all required fields So that employee data is accurate and complete.
Acceptance Criteria:
Scenario: Employee creation with unique badgeId
Given I have employee details
When I POST to /employees
Then the employee is created with a unique badgeId
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique

---

Title: Employee Master Data - Update Employee
User Story: As an HR I want to update employee details So that records remain current and accurate.
Acceptance Criteria:
Scenario: Update employee information
Given an employee exists
When I PUT/PATCH to /employees/{id}
Then the employee details are updated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: OpenAPI schema must reflect all fields

---

Title: Employee Master Data - Delete Employee (Soft Delete)
User Story: As an HR I want to soft-delete employee records So that historical data is preserved for compliance.
Acceptance Criteria:
Scenario: Soft delete employee
Given an employee exists
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Deleted employees are excluded from active queries

---

Title: Employee Master Data - List & Filter Employees
User Story: As an HR I want to list and filter employees by department, role, and status So that I can quickly find relevant records.
Acceptance Criteria:
Scenario: Filter employees
Given multiple employees exist
When I GET /employees with filters
Then the response contains only matching employees, paginated
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: Pagination and filtering required
