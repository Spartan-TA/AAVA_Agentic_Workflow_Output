Title: Employee Domain CRUD API

User Story: As an HR manager I want to create, read, update, and delete employee records So that employee data is managed centrally

Acceptance Criteria:
Scenario: Create employee
Given valid employee details
When I POST to /employees
Then a new employee record is created with a unique badgeId

Scenario: Update employee
Given an existing employee
When I PUT/PATCH to /employees/{id}
Then the employee record is updated

Scenario: Delete employee (soft-delete)
Given an existing employee
When I DELETE /employees/{id}
Then the employee is soft-deleted and excluded from active queries

Scenario: List employees with pagination/filtering
Given multiple employee records
When I GET /employees with filters
Then only matching employees are returned, paginated

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project scaffolding
- Notes: OpenAPI schemas must include examples

Title: Implement Role-Based Access Control

User Story: As an administrator I want to restrict access to sensitive endpoints based on user roles So that only authorized users can perform critical actions

Acceptance Criteria:
Scenario: Unauthorized request
Given a user without authentication
When they access a protected endpoint
Then a 401 Unauthorized response is returned

Scenario: Forbidden action
Given a user with insufficient role
When they attempt a restricted action
Then a 403 Forbidden response is returned

Scenario: ADMIN role access
Given a user with ADMIN role
When they manage employee records
Then all actions are permitted

Scenario: SUPERVISOR role access
Given a user with SUPERVISOR role
When they manage team records
Then only their team's records are accessible

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Employee CRUD, Project scaffolding
- Notes: Security rules must be covered by tests
