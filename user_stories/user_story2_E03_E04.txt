### E03: Role-Based Access Control (RBAC)

**User Story 1**
Title: Enforce Role Permissions
User Story: As an ADMIN I want to manage user roles and permissions So that sensitive operations are restricted
Acceptance Criteria:
Scenario: Unauthorized access
Given a user without ADMIN role
When they attempt to access /admin endpoints
Then they receive a 403 Forbidden error
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01, E02
Notes: Security rules must be covered by tests

**User Story 2**
Title: Row-Level Security
User Story: As a SUPERVISOR I want to access only my team's data So that I cannot view or edit other teams
Acceptance Criteria:
Scenario: Team data access
Given a SUPERVISOR
When accessing employee records
Then only records for their team are visible
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Row-level constraints enforced

**User Story 3**
Title: API Key/OAuth2 Toggle
User Story: As a DEVOPS ENGINEER I want to switch between API key and OAuth2 authentication So that integration is flexible
Acceptance Criteria:
Scenario: Auth toggle
Given a configuration setting
When I change the auth mode
Then the application enforces the selected authentication method
Additional Details:
Priority: Medium
Story Points: 2
Dependencies: E01
Notes: Documented in README

**User Story 4**
Title: Unauthorized Request Handling
User Story: As a USER I want unauthorized requests to be handled gracefully So that security is maintained
Acceptance Criteria:
Scenario: Unauthorized request
Given a user without credentials
When accessing a protected endpoint
Then a 401 Unauthorized response is returned
Additional Details:
Priority: High
Story Points: 1
Dependencies: E01
Notes: Standardized error messages

### E04: Time & Attendance (Clock In/Out)

**User Story 1**
Title: Employee Clock-In
User Story: As a WORKER I want to clock in at the start of my shift So that my attendance is recorded
Acceptance Criteria:
Scenario: Clock-in
Given I am scheduled for a shift
When I POST to /attendance/clock-in
Then my clock-in event is recorded with timestamp and location
Additional Details:
Priority: High
Story Points: 3
Dependencies: E02, E03
Notes: Geofence optional

**User Story 2**
Title: Handle Missed Punches
User Story: As a SUPERVISOR I want to approve corrections for missed punches So that attendance data is accurate
Acceptance Criteria:
Scenario: Missed punch correction
Given a missed clock-in
When a correction is submitted
Then an approval task is created for the supervisor
Additional Details:
Priority: High
Story Points: 2
Dependencies: E02, E03
Notes: Corrections workflow required

**User Story 3**
Title: Calculate Hours Worked
User Story: As an HR I want daily totals of hours worked per employee So that payroll is accurate
Acceptance Criteria:
Scenario: Hours calculation
Given valid clock-in/out events
When the day ends
Then total hours worked are computed and available for export
Additional Details:
Priority: High
Story Points: 2
Dependencies: E02, E03
Notes: Exportable as CSV

**User Story 4**
Title: Device Capture for Clock Events
User Story: As an ADMIN I want to capture device info during clock-in/out So that I can audit attendance authenticity
Acceptance Criteria:
Scenario: Device capture
Given a clock-in/out event
When the event is recorded
Then device details are stored with the event
Additional Details:
Priority: Medium
Story Points: 1
Dependencies: E02, E03
Notes: Device info includes IP and device ID
