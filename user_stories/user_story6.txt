Title: Enforce Unique Badge ID and Support Pagination/Filtering
User Story: As an HR Manager I want to ensure each employee has a unique badgeId and can search/filter employee records So that duplicate entries are prevented and large datasets are manageable
Acceptance Criteria:
Scenario: Unique badgeId enforcement
Given I attempt to create or update an employee
When I use a badgeId that already exists
Then the system should reject the request with a validation error
Scenario: Pagination and filtering
Given there are many employee records
When I request a paginated or filtered list via the API
Then I should receive only the relevant subset of records
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Employee CRUD APIs (E02)
- Notes: OpenAPI schemas should include examples for these cases.
