### E03: Role-Based Access Control (RBAC)

**Epic Description:**
Add Spring Security with roles (ADMIN, HR, SUPERVISOR, WORKER); method/endpoint security and row-level constraints where applicable; API key/OAuth2 toggle via config.

---

**User Story 1: Implement Role-Based Endpoint Security**

Title: Secure Endpoints by Role

User Story: As an admin, I want endpoints secured by user role so that only authorized users can perform sensitive operations.

Acceptance Criteria:

Scenario: Unauthorized request returns 401
  Given I am not authenticated
  When I access a protected endpoint
  Then I receive a 401 Unauthorized response

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Use Spring Security annotations.

---

**User Story 2: Implement Forbidden Action Handling**

Title: Restrict Actions Based on Role

User Story: As a supervisor, I want to be prevented from accessing admin-only features so that security boundaries are enforced.

Acceptance Criteria:

Scenario: Forbidden action returns 403
  Given I am authenticated as SUPERVISOR
  When I attempt an admin-only action
  Then I receive a 403 Forbidden response

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Test all role boundaries.

---

**User Story 3: Admin Full Access**

Title: Allow Admins to Manage All Records

User Story: As an admin, I want full access to manage all records so that I can perform system-wide operations.

Acceptance Criteria:

Scenario: Admin can manage all records
  Given I am authenticated as ADMIN
  When I perform any CRUD operation
  Then the action is permitted

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: None

---

**User Story 4: Supervisor Row-Level Constraints**

Title: Limit Supervisors to Team Records

User Story: As a supervisor, I want to access only my team's records so that I cannot view or edit other teams' data.

Acceptance Criteria:

Scenario: Supervisor limited to team data
  Given I am authenticated as SUPERVISOR
  When I access employee data
  Then I only see employees assigned to my team

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Implement row-level security.

---

**User Story 5: API Key/OAuth2 Toggle**

Title: Support API Key and OAuth2 Authentication

User Story: As a DevOps engineer, I want to toggle between API key and OAuth2 authentication via config so that I can adapt to different security requirements.

Acceptance Criteria:

Scenario: Authentication method toggled via config
  Given the application is configured for API key or OAuth2
  When I authenticate using the selected method
  Then access is granted or denied accordingly

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Document configuration steps.

---

**User Story 6: Security Test Coverage**

Title: Cover Security Rules with Automated Tests

User Story: As a QA engineer, I want automated tests for security rules so that unauthorized access is prevented.

Acceptance Criteria:

Scenario: Security rules covered by tests
  Given the test suite runs
  When security tests execute
  Then all role-based access rules are validated

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Include negative test cases.
