# E02: Employee Master Data (CRUD)

## User Story 1: Create Employee Record
**User Story:**  
As an HR user, I want to create a new employee record with all required fields so that employee data is centralized.

**Acceptance Criteria (Gherkin):**
```
Given I have HR role
When I POST to /employees with valid data
Then a new employee is created with a unique badgeId

Given I POST to /employees with a duplicate badgeId
Then the request is rejected with an error
```

**Additional Details:**  
Priority: High  
Story Points: 3  
Dependencies: E01  
Notes: badgeId must be unique.

---

## User Story 2: Retrieve Employee Records with Filtering and Pagination
**User Story:**  
As an HR user, I want to retrieve employee records with filtering and pagination so that I can efficiently manage large datasets.

**Acceptance Criteria (Gherkin):**
```
Given I GET /employees with filter parameters
When results are returned
Then only matching employees are shown, paginated

Given I GET /employees?page=2&size=10
Then I receive the correct page of results
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: E01  
Notes: Support filtering by department, status, etc.

---

## User Story 3: Update Employee Record
**User Story:**  
As an HR user, I want to update employee details so that records remain current.

**Acceptance Criteria (Gherkin):**
```
Given an existing employee
When I PATCH /employees/{id} with valid changes
Then the employee record is updated

Given I PATCH with invalid data
Then the request is rejected with an error
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: E01  
Notes: Validate all fields.

---

## User Story 4: Soft-Delete Employee Record
**User Story:**  
As an HR user, I want to soft-delete employee records so that historical data is preserved.

**Acceptance Criteria (Gherkin):**
```
Given an existing employee
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database

Given I GET /employees
Then soft-deleted employees are excluded by default
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: E01  
Notes: Add a "deleted" flag.

---

## User Story 5: Provide OpenAPI Schemas with Examples
**User Story:**  
As a developer, I want OpenAPI documentation with request/response examples for employee APIs so that integration is easier.

**Acceptance Criteria (Gherkin):**
```
Given the API is deployed
When I access /swagger-ui or /openapi.json
Then I see schemas and example payloads for all employee endpoints
```

**Additional Details:**  
Priority: High  
Story Points: 1  
Dependencies: E01  
Notes: Keep documentation up to date.
