### E16 - Mobile Access (PWA)

#### User Story 1: Responsive Mobile Views for Core Flows
- **Title:** Responsive Mobile Views for Core Flows
- **User Story:** As a WORKER, I want to clock in/out, view schedules, request leave, and see announcements on my mobile device so that I can manage my work on the go.
- **Acceptance Criteria:**
    - Given a mobile device,
      When I access the app,
      Then all core flows are usable and responsive.
- **Priority:** Medium
- **Story Points:** 5
- **Dependencies:** E04, E05, E06, E12
- **Notes:** Mobile-first design.

#### User Story 2: Installable PWA Manifest
- **Title:** Installable PWA Manifest
- **User Story:** As a USER, I want to install the app as a PWA so that I can access it like a native app.
- **Acceptance Criteria:**
    - Given the app,
      When I add it to my home screen,
      Then it installs with an icon and manifest.
- **Priority:** Medium
- **Story Points:** 2
- **Dependencies:** E16-1
- **Notes:** Improves adoption.

#### User Story 3: Offline Queue for Clock Events
- **Title:** Offline Queue for Clock Events
- **User Story:** As a WORKER, I want to clock in/out even when offline so that my attendance is not lost.
- **Acceptance Criteria:**
    - Given no network,
      When I clock in/out,
      Then the event is queued locally.
    - Given restored connectivity,
      When the app syncs,
      Then queued events are submitted and conflicts are resolved.
- **Priority:** Medium
- **Story Points:** 3
- **Dependencies:** E16-1
- **Notes:** Offline support.

#### User Story 4: Lighthouse PWA Score Compliance
- **Title:** Achieve High Lighthouse PWA Score
- **User Story:** As a PRODUCT OWNER, I want the app to score highly on Lighthouse PWA audits so that quality is assured.
- **Acceptance Criteria:**
    - Given a Lighthouse audit,
      When run,
      Then the PWA score is 90+.
- **Priority:** Medium
- **Story Points:** 1
- **Dependencies:** E16-1
- **Notes:** Quality metric.
