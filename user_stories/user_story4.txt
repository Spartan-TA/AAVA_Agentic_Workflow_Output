Title: Employee CRUD API
User Story: As an HR user, I want to create, read, update, and delete employee records so that employee data is accurate and up to date.
Acceptance Criteria:
  Given the API is running,
  When I POST/GET/PUT/PATCH/DELETE to /employees,
  Then the operations succeed and data is persisted.

  Given a badgeId is reused,
  When I try to create a new employee,
  Then the system rejects the request due to uniqueness.

  Given an employee is deleted,
  When I query employees,
  Then the deleted employee is not returned (soft-delete).

Additional Details:
  Priority: High
  Story Points: 5
  Dependencies: Project Scaffolding
  Notes: Supports pagination and filtering.
