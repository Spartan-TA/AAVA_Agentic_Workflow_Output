Title: Create Employee CRUD APIs

User Story: As an HR manager I want to create, read, update, and delete employee records via API So that employee data is managed centrally

Acceptance Criteria:

Scenario: Create employee with unique badgeId
Given a valid employee payload with a unique badgeId
When I POST to /employees
Then the employee is created and returned

Scenario: Update employee details
Given an existing employee
When I PUT or PATCH to /employees/{id} with valid data
Then the employee record is updated

Scenario: Soft-delete employee
Given an existing employee
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database

Scenario: Pagination and filtering
Given multiple employees exist
When I GET /employees with pagination and filter parameters
Then I receive a paginated, filtered list of employees

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project Scaffolding
- Notes: Enforce unique badgeId at DB and API; return OpenAPI schema with examples; support search by name, department, status
