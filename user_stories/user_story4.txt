Title: Implement Employee CRUD APIs

User Story: As an HR manager I want to create, read, update, and delete employee records So that I can maintain accurate employee master data

Acceptance Criteria:
Scenario: Create employee
  Given valid employee details
  When I POST to /employees
  Then a new employee record should be created with a unique badgeId
Scenario: Update employee
  Given an existing employee
  When I PUT or PATCH to /employees/{id}
  Then the employee record should be updated
Scenario: Delete employee
  Given an employee record
  When I DELETE /employees/{id}
  Then the employee should be soft-deleted and excluded from active lists
Scenario: List employees
  Given multiple employee records
  When I GET /employees with pagination and filters
  Then I should receive a paginated, filtered list

Additional Details:
- Priority: High
- Story Points: 8
- Dependencies: Project scaffolding (E01)
- Notes: OpenAPI schemas must be provided; badgeId must be unique
