Title: Clock-In/Clock-Out Event Endpoints

User Story:
As a warehouse worker, I want to clock in and out using a secure endpoint so that my worked hours are accurately recorded for payroll and compliance.

Acceptance Criteria:
- Scenario: Valid clock-in event
  Given a worker is authenticated
  When they POST to /attendance/clock-in with valid data
  Then the event is recorded and associated with their shift

- Scenario: Valid clock-out event
  Given a worker is authenticated
  When they POST to /attendance/clock-out with valid data
  Then the event is recorded and shift hours are calculated

- Scenario: Invalid or duplicate clock-in/out
  Given a worker attempts to clock in/out twice for the same shift
  When they POST to the endpoint
  Then the response is 400 Bad Request

Additional Details:
- Device and optional geofence data must be captured
- Automatic shift association based on schedule
- API must validate event sequence and data integrity
