Title: E04-1 Clock In/Out Endpoints

User Story:
As an employee,
I want to clock in and out via secure API endpoints,
So that my work hours are accurately recorded in the system.

Acceptance Criteria:
Given an authenticated employee,
When they call the clock-in endpoint,
Then a new clock-in event is recorded with timestamp, location (if available), and device info.

Given an authenticated employee,
When they call the clock-out endpoint,
Then a clock-out event is recorded and paired with the latest clock-in event.

Given an invalid or duplicate clock event,
When the endpoint is called,
Then the request is rejected with a clear error message.

Additional Details:
- Endpoints must validate user identity and prevent spoofing.
- Clock events must be auditable and tamper-evident.
- API must be documented in OpenAPI spec.
- Support for mobile and web clients.
