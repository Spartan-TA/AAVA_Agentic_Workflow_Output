Title: Document Employee CRUD APIs in OpenAPI Schemas

User Story: As a developer I want Employee CRUD APIs documented in OpenAPI schemas with examples So that integration and onboarding are streamlined for other teams.

Acceptance Criteria:
Scenario: OpenAPI schema available
  Given the API endpoints for employees
  When I view the OpenAPI documentation
  Then all CRUD endpoints are described with request/response examples
Scenario: Example data
  Given the OpenAPI schema
  When I view the employee model
  Then I see example values for all fields (name, badgeId, role, etc.)
Scenario: Schema validation
  Given the OpenAPI schema
  When I generate client code
  Then the code matches the API contract

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: user_story_6.txt, user_story_7.txt, user_story_8.txt, user_story_9.txt
- Notes: Schemas must be versioned and updated with every API change.
