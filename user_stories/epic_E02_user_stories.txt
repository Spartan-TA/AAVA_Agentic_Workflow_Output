### E02: Employee Master Data (CRUD)

**User Story 1: Create Employee Record**
User Story: As an HR user I want to create employee records So that new hires are registered in the system
Acceptance Criteria:
Scenario: Create employee
Given I have valid employee data
When I POST to /employees
Then a new employee is created with a unique badgeId
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique.

**User Story 2: Update and Soft-Delete Employee**
User Story: As an HR user I want to update or soft-delete employee records So that employee data stays current without losing history
Acceptance Criteria:
Scenario: Soft-delete employee
Given an employee exists
When I PATCH /employees/{id} with status=inactive
Then the employee is marked as inactive and not deleted from the database
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Soft-delete only.

**User Story 3: List and Filter Employees**
User Story: As a supervisor I want to list and filter employees So that I can find relevant staff quickly
Acceptance Criteria:
Scenario: Filter employees by department
Given employees exist in multiple departments
When I GET /employees?department=Shipping
Then only employees in Shipping are returned
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Pagination required.

**User Story 4: OpenAPI Documentation for Employee APIs**
User Story: As a developer I want OpenAPI docs for employee endpoints So that integration is straightforward
Acceptance Criteria:
Scenario: View OpenAPI docs
Given the API is running
When I access /swagger-ui
Then employee endpoints are documented with request/response examples
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Use Swagger/OpenAPI.
