### E14 - Audit Trail & Compliance

**User Story 1**
- Title: Log Sensitive Changes with Actor and Timestamp
- User Story: As a compliance officer, I want every create/update/delete logged with actor and timestamp so that changes are traceable.
- Acceptance Criteria:
  - Given a sensitive change occurs,
    When I view the audit log,
    Then actor and timestamp are recorded.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E03, Notes: Traceability.

**User Story 2**
- Title: Store Before/After Values in Immutable Log Table
- User Story: As a compliance officer, I want before/after values stored in an immutable log so that forensic analysis is possible.
- Acceptance Criteria:
  - Given a change occurs,
    When I view the log,
    Then before and after values are visible and cannot be altered.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E03, Notes: Forensics.

**User Story 3**
- Title: Export Audit Logs by Date/User/Entity
- User Story: As a compliance officer, I want to export audit logs by date, user, or entity so that investigations are efficient.
- Acceptance Criteria:
  - Given logs exist,
    When I filter and export,
    Then only relevant entries are included.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E03, Notes: Investigation support.

**User Story 4**
- Title: Automated Tests Validate Audit Coverage
- User Story: As a developer, I want automated tests to validate audit coverage so that no sensitive change is missed.
- Acceptance Criteria:
  - Given tests are written,
    When I run them,
    Then all sensitive changes are logged.
- Additional Details: Priority: High, Story Points: 1, Dependencies: E03, Notes: Test coverage.
