## E03: Role Based Access Control (RBAC)

### User Story 1: Endpoint Security by Role
**User Story:** As an ADMIN I want to restrict endpoints by user role So that only authorized users can perform sensitive actions.

**Acceptance Criteria:**
- Scenario: Unauthorized access
  - Given a user without HR role
  - When they POST to `/employees`
  - Then the response is 403 Forbidden

- Scenario: ADMIN can access all endpoints
  - Given an ADMIN user
  - When they access any endpoint
  - Then access is granted

**Priority:** High  
**Story Points:** 5  
**Dependencies:** E01, E02  
**Notes:** Security rules must be covered by tests.

---

### User Story 2: Row-Level Security for Supervisors
**User Story:** As a SUPERVISOR I want to access only my team's records So that I cannot view or modify other teams.

**Acceptance Criteria:**
- Scenario: Supervisor sees only their team
  - Given a supervisor assigned to Team A
  - When they GET `/employees`
  - Then only Team A employees are returned

- Scenario: Supervisor attempts to update other team
  - Given a supervisor for Team A
  - When they PATCH an employee from Team B
  - Then the response is 403 Forbidden

**Priority:** High  
**Story Points:** 8  
**Dependencies:** E01, E02  
**Notes:** Team assignment must be enforced.

---

### User Story 3: OAuth2 and API Key Toggle
**User Story:** As a system admin I want to toggle between OAuth2 and API key authentication So that integration is flexible.

**Acceptance Criteria:**
- Scenario: OAuth2 enabled
  - Given OAuth2 is configured
  - When a request is made with a valid token
  - Then access is granted

- Scenario: API key enabled
  - Given API key is configured
  - When a request is made with a valid key
  - Then access is granted

- Scenario: No credentials
  - Given no credentials
  - When a request is made
  - Then the response is 401 Unauthorized

**Priority:** High  
**Story Points:** 8  
**Dependencies:** E01, E02  
**Notes:** Configurable via application properties.

---

### User Story 4: Security Test Coverage
**User Story:** As a QA I want automated tests for all security rules So that unauthorized access is prevented.

**Acceptance Criteria:**
- Scenario: Test for forbidden actions
  - Given a non-ADMIN user
  - When they attempt restricted actions
  - Then tests assert 403 is returned

**Priority:** High  
**Story Points:** 3  
**Dependencies:** E01, E02  
**Notes:** Must cover all roles.
