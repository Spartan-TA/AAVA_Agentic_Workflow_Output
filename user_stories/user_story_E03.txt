### E03 - Role-Based Access Control (RBAC)

**User Story 1: Role Assignment**
- Title: Assign Roles to Users
- User Story: As an admin, I want to assign roles (ADMIN, HR, SUPERVISOR, WORKER) to users so that access is controlled.
- Acceptance Criteria:
  - Given a user, When I assign a role, Then the user has permissions according to their role.
  - Given an unauthorized user, When they access restricted endpoints, Then they receive a 401 error.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E01, E02, Notes: Use Spring Security.

**User Story 2: Endpoint Security**
- Title: Secure Endpoints by Role
- User Story: As a developer, I want to secure endpoints so that only authorized roles can perform sensitive operations.
- Acceptance Criteria:
  - Given a SUPERVISOR, When they access team data, Then access is granted.
  - Given a WORKER, When they access admin data, Then access is forbidden (403).
- Additional Details: Priority: High, Story Points: 3, Dependencies: E01, E02, Notes: Row-level constraints.

**User Story 3: API Key/OAuth2 Toggle**
- Title: Configurable Auth Method
- User Story: As a system admin, I want to toggle between API key and OAuth2 authentication so that integration flexibility is maintained.
- Acceptance Criteria:
  - Given the config is set to API key, When I authenticate, Then API key is required.
  - Given the config is set to OAuth2, When I authenticate, Then OAuth2 flow is enforced.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Document toggle steps.

**User Story 4: Security Test Coverage**
- Title: Automated Security Tests
- User Story: As a QA engineer, I want automated tests for security rules so that unauthorized access is prevented.
- Acceptance Criteria:
  - Given test cases, When I run security tests, Then all rules are validated and unauthorized actions are blocked.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Cover all roles.
