### Epic E03 - Role Based Access Control (RBAC)

**User Story 1**
- Title: Implement Role-Based Endpoint Security
- User Story: As a system administrator, I want endpoints secured by roles (ADMIN, HR, SUPERVISOR, WORKER) so that sensitive operations are restricted.
- Acceptance Criteria:
  - Given a user with insufficient role,
    When accessing a protected endpoint,
    Then a 403 Forbidden is returned.
  - Given an unauthenticated request,
    When accessing any endpoint,
    Then a 401 Unauthorized is returned.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E01, E02, Notes: Covers all sensitive endpoints.

**User Story 2**
- Title: Row-Level Security for Employee Data
- User Story: As a supervisor, I want access limited to my team's employee records so that privacy is maintained.
- Acceptance Criteria:
  - Given a supervisor,
    When accessing employee data,
    Then only records for their team are visible.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Row-level constraints.

**User Story 3**
- Title: API Key/OAuth2 Toggle
- User Story: As a system administrator, I want to toggle between API key and OAuth2 authentication via config so that integration flexibility is provided.
- Acceptance Criteria:
  - Given the config is set to API key,
    When authenticating,
    Then API key is required.
  - Given the config is set to OAuth2,
    When authenticating,
    Then OAuth2 flow is enforced.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Configurable security.

**User Story 4**
- Title: Security Test Coverage
- User Story: As a QA engineer, I want automated tests for security rules so that unauthorized actions are reliably blocked.
- Acceptance Criteria:
  - Given the test suite,
    When running security tests,
    Then all role restrictions are validated.
- Additional Details: Priority: High, Story Points: 1, Dependencies: E01, E02, Notes: Ensures coverage.
