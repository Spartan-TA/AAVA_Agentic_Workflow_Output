[E03] Role-Based Access Control (RBAC)

User Story 1
Title: Integrate Spring Security with Role Definitions
User Story: As a system administrator, I want to define roles (ADMIN, HR, SUPERVISOR, WORKER) so that access is controlled.
Acceptance Criteria:
  Scenario: Roles defined
    Given the application is running
    When I assign a user a role
    Then the user has permissions according to their role
Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Roles stored in DB/config

User Story 2
Title: Secure Endpoints and Methods by Role
User Story: As a system administrator, I want to secure endpoints and methods so that only authorized roles can access sensitive operations.
Acceptance Criteria:
  Scenario: Endpoint access control
    Given a user with insufficient role
    When they access a restricted endpoint
    Then they receive a 403 Forbidden response
Additional Details: Priority: High, Story Points: 3, Dependencies: E03-1, Notes: Use method/endpoint security

User Story 3
Title: Enforce Row-Level Security Where Applicable
User Story: As a supervisor, I want to access only my team's records so that data privacy is maintained.
Acceptance Criteria:
  Scenario: Row-level constraints
    Given a supervisor is logged in
    When they list employees
    Then only their team's records are returned
Additional Details: Priority: High, Story Points: 3, Dependencies: E03-2, Notes: Team assignment logic

User Story 4
Title: Support API Key/OAuth2 Toggle via Config
User Story: As a DevOps engineer, I want to toggle between API Key and OAuth2 authentication cost-free so that integration is flexible.
Acceptance Criteria:
  Scenario: Auth mode toggle
    Given the application is running
    When I change the config
    Then the authentication mode switches between API Key and OAuth2
Additional Details: Priority: High, Story Points: 2, Dependencies: E03-1, Notes: Configurable at startup

User Story 5
Title: Return 401 for Unauthorized and 403 for Forbidden
User Story: As a developer, I want the API to return 401 for unauthorized and 403 for forbidden actions so that clients can handle errors correctly.
Acceptance Criteria:
  Scenario: Unauthorized and forbidden responses
    Given a user is not authenticated or not authorized
    When they access a protected endpoint
    Then the API returns 401 or 403 as appropriate
Additional Details: Priority: High, Story Points: 1, Dependencies: E03-2, Notes: Standard HTTP codes

User Story 6
Title: Cover Security Rules with Automated Tests
User Story: As a QA engineer, I want automated tests for security rules so that access control is reliably enforced.
Acceptance Criteria:
  Scenario: Security test coverage
    Given the test suite runs
    When security tests execute
    Then all access rules are validated and covered
Additional Details: Priority: High, Story Points: 2, Dependencies: E03-2, Notes: Use integration tests
