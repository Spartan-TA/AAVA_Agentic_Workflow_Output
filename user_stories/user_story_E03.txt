### E03 - Role Based Access Control (RBAC)

**Title:** Implement Role-Based Endpoint Security
User Story: As a system administrator I want to restrict API endpoints by role (ADMIN, HR, SUPERVISOR, WORKER) So that only authorized users can perform sensitive actions
Acceptance Criteria:
Scenario: Unauthorized request
Given a user without a valid token
When they access a protected endpoint
Then the response is 401 Unauthorized
Scenario: Forbidden action
Given a SUPERVISOR
When they try to delete an employee outside their team
Then the response is 403 Forbidden
Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: E01, E02
- Notes: Security rules covered by automated tests

**Title:** Support API Key/OAuth2 Toggle
User Story: As a DevOps engineer I want to toggle between API key and OAuth2 authentication via config So that integration partners can use the preferred method
Acceptance Criteria:
Scenario: API key enabled
Given config is set to API key
When a request includes a valid key
Then access is granted
Scenario: OAuth2 enabled
Given config is set to OAuth2
When a request includes a valid token
Then access is granted
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Implement Role-Based Endpoint Security
- Notes: Document toggle in README

**Title:** Enforce Row-Level Security
User Story: As a supervisor I want to only access employee records for my team So that privacy is maintained
Acceptance Criteria:
Scenario: SUPERVISOR access
Given a SUPERVISOR
When they GET `/employees`
Then only their team's records are returned
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Implement Role-Based Endpoint Security
- Notes: Row-level constraints in service layer
