### E03 - Role-Based Access Control (RBAC)

**User Story 1**
Title: Implement Role-Based Security
User Story: As a system admin, I want to restrict access to endpoints based on roles (ADMIN, HR, SUPERVISOR, WORKER) So that sensitive operations are protected.
Acceptance Criteria:
- Given a user with no token, When accessing a protected endpoint, Then return 401 Unauthorized.
- Given a user with insufficient role, When accessing a restricted endpoint, Then return 403 Forbidden.
Additional Details: Priority: High, Story Points: 5, Dependencies: E01, E02, Notes: Role mapping.

**User Story 2**
Title: Row-Level Security for Supervisors
User Story: As a supervisor, I want to access only my team's records So that I cannot view or modify other teams.
Acceptance Criteria:
- Given a supervisor, When accessing employee data, Then only team members are visible/editable.
Additional Details: Priority: High, Story Points: 3, Dependencies: E01, E02, Notes: Team mapping.

**User Story 3**
Title: API Key/OAuth2 Toggle
User Story: As a system admin, I want to toggle between API key and OAuth2 authentication via config So that integration flexibility is maintained.
Acceptance Criteria:
- Given the config, When I set auth mode to API key, Then endpoints require API key.
- When set to OAuth2, Then endpoints require OAuth2 tokens.
Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Configurable.

**User Story 4**
Title: Security Test Coverage
User Story: As a QA, I want automated tests for security rules So that unauthorized actions are prevented.
Acceptance Criteria:
- Given test cases, When running security tests, Then all role restrictions are validated.
Additional Details: Priority: High, Story Points: 2, Dependencies: E01, E02, Notes: Automated tests.
