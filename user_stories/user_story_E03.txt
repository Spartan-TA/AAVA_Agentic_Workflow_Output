### E03: Role Based Access Control (RBAC)

**User Story 1**
Title: Implement Role-Based Endpoint Security
User Story: As an ADMIN I want endpoints secured by role So that only authorized users can perform sensitive actions
Acceptance Criteria:
Scenario: Unauthorized access
Given a user without ADMIN role
When they attempt to POST to `/employees`
Then they receive a 403 Forbidden response
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: All endpoints must be covered by tests

**User Story 2**
Title: Row-Level Security for Supervisors
User Story: As a SUPERVISOR I want to access only my team's records So that I cannot view or edit other teams
Acceptance Criteria:
Scenario: Supervisor access
Given a supervisor assigned to Team A
When they GET `/employees`
Then only employees in Team A are returned
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Team assignment enforced at query level

**User Story 3**
Title: API Key/OAuth2 Toggle
User Story: As a DEVOPS ENGINEER I want to toggle between API key and OAuth2 authentication via config So that security can be adapted to environment
Acceptance Criteria:
Scenario: Switch authentication mode
Given the config is set to API key
When I call an endpoint with a valid API key
Then access is granted
And when config is set to OAuth2
Then only OAuth2 tokens are accepted
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Documented in README

**User Story 4**
Title: Unauthorized Requests Return 401
User Story: As a USER I want unauthorized requests to return 401 So that security feedback is clear
Acceptance Criteria:
Scenario: No credentials
Given no authentication is provided
When I call a protected endpoint
Then I receive a 401 Unauthorized
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01, E02
- Notes: Applies to all protected endpoints
