### Epic E03: Role Based Access Control (RBAC)

**User Story 1**
Title: Secure Endpoints by Role
User Story: As a system admin, I want endpoints secured by role (ADMIN, HR, SUPERVISOR, WORKER) so that only authorized users can perform sensitive actions.
Acceptance Criteria:
Scenario: Role-Based Access
Given a user with a role
When accessing a protected endpoint
Then unauthorized requests return 401, forbidden actions return 403
Priority: High
Story Points: 3
Dependencies: E01, E02
Notes: Security rules must be covered by tests.

**User Story 2**
Title: Row-Level Security for Supervisors
User Story: As a supervisor, I want to access only my team's records so that data privacy is maintained.
Acceptance Criteria:
Scenario: Supervisor Data Access
Given a supervisor user
When accessing employee data
Then only team members' records are visible
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Row-level constraints enforced.

**User Story 3**
Title: API Key/OAuth2 Toggle
User Story: As a system admin, I want to toggle between API key and OAuth2 authentication via config so that integration flexibility is supported.
Acceptance Criteria:
Scenario: Auth Toggle
Given a config setting
When I change the authentication mode
Then endpoints require the selected auth method
Priority: High
Story Points: 2
Dependencies: E01, E02
Notes: Documented in README.
