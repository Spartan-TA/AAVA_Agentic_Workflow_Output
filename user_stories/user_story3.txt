### E03 - Role-Based Access Control (RBAC)

**User Story 1**
Title: Implement Role Definitions and Assignment
User Story: As an admin I want to define roles (ADMIN, HR, SUPERVISOR, WORKER) and assign them to users So that access is controlled based on responsibilities.
Acceptance Criteria:
Scenario: Roles assigned to users
Given a user exists
When I assign a role
Then the user has the correct permissions
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01, E02
- Notes: Roles stored in DB or external IDP

**User Story 2**
Title: Secure Endpoints with Method and Row-Level Security
User Story: As a developer I want to secure API endpoints and data access based on user roles So that unauthorized access is prevented.
Acceptance Criteria:
Scenario: Access control enforced
Given a SUPERVISOR user
When they access employee data outside their team
Then the API returns 403 Forbidden
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E03-1
- Notes: Use Spring Security annotations

**User Story 3**
Title: Support API Key/OAuth2 Toggle
User Story: As a DevOps engineer I want to toggle between API key and OAuth2 authentication via configuration So that security can be adapted to environment needs.
Acceptance Criteria:
Scenario: Auth mode switch
Given the config is set to API key
When I call an endpoint with a valid key
Then access is granted
And when set to OAuth2, only valid tokens are accepted
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03-1
- Notes: Document how to switch modes

**User Story 4**
Title: Return Proper HTTP Status for Unauthorized/Forbidden
User Story: As a user I want the system to return 401 for unauthorized and 403 for forbidden actions So that API consumers can handle errors correctly.
Acceptance Criteria:
Scenario: Unauthorized and forbidden responses
Given I am not authenticated
When I call a protected endpoint
Then I receive 401 Unauthorized
Given I am authenticated but lack permission
When I call a restricted endpoint
Then I receive 403 Forbidden
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E03-2
- Notes: Cover with automated tests

**User Story 5**
Title: Test Coverage for Security Rules
User Story: As a QA engineer I want automated tests for all security rules So that regressions are caught early.
Acceptance Criteria:
Scenario: Security tests run
Given the test suite is executed
When security rules are evaluated
Then all access control scenarios are covered
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03-2
- Notes: Include both positive and negative tests
