Title: Role-Based Access Control (RBAC)
User Story 1: As an admin I want to assign roles (ADMIN, HR, SUPERVISOR, WORKER) to users So that access is controlled
Acceptance Criteria:
Scenario: Role assignment
Given a user exists
When I assign a role
Then the user receives appropriate permissions
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Employee master data
- Notes: Roles stored in DB

User Story 2: As a system I want to restrict sensitive endpoints based on roles So that only authorized users can perform actions
Acceptance Criteria:
Scenario: Endpoint security
Given endpoints are secured
When a user accesses a restricted endpoint
Then unauthorized users receive 401 or 403
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Role assignment
- Notes: Cover with unit tests

User Story 3: As an admin I want to toggle API key/OAuth2 authentication via config So that security can be adapted
Acceptance Criteria:
Scenario: Auth toggle
Given the config is set
When I switch between API key and OAuth2
Then authentication method changes accordingly
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Project scaffolding
- Notes: Document config options

User Story 4: As a supervisor I want to be limited to managing my team So that data privacy is maintained
Acceptance Criteria:
Scenario: Row-level security
Given a supervisor is logged in
When accessing employee data
Then only team members are visible/editable
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Role assignment
- Notes: Enforce via DB queries

User Story 5: As a QA engineer I want security rules covered by tests So that vulnerabilities are minimized
Acceptance Criteria:
Scenario: Security test coverage
Given security rules are implemented
When tests are run
Then all rules are validated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Endpoint security
- Notes: Include negative cases
