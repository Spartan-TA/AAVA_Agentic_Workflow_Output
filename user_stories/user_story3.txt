---
EPIC E03: Role-Based Access Control (RBAC)

User Story 1:
Title: Implement Role-Based Authentication
User Story: As an admin, I want to authenticate users and assign roles so that access is controlled.
Acceptance Criteria in Gherkin:
Scenario: User authentication and role assignment
  Given a user account
  When I log in
  Then my role (ADMIN, HR, SUPERVISOR, WORKER) is assigned and persisted
Additional Details:
  Priority: High
  Story Points: 3
  Dependencies: E01, E02
  Notes: Use Spring Security

User Story 2:
Title: Secure Endpoints by Role
User Story: As a system, I want to restrict endpoint access based on user roles so that sensitive operations are protected.
Acceptance Criteria in Gherkin:
Scenario: Endpoint security enforcement
  Given a user with insufficient role
  When I access a restricted endpoint
  Then I receive a 403 Forbidden response
Additional Details:
  Priority: High
  Story Points: 3
  Dependencies: E01, E02
  Notes: Method/endpoint security annotations

User Story 3:
Title: Support API Key/OAuth2 Toggle via Config
User Story: As an admin, I want to toggle between API key and OAuth2 authentication so that integration flexibility is maintained.
Acceptance Criteria in Gherkin:
Scenario: Authentication toggle
  Given the config is set to API key
  When I authenticate
  Then API key authentication is enforced
  And when config is set to OAuth2
  Then OAuth2 authentication is enforced
Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: E01, E02
  Notes: Configurable via properties

User Story 4:
Title: Enforce Row-Level Security for Supervisors
User Story: As a supervisor, I want to access only my team's records so that privacy is maintained.
Acceptance Criteria in Gherkin:
Scenario: Row-level access
  Given a supervisor user
  When I query employee records
  Then I see only employees in my assigned team
Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: E01, E02
  Notes: Add team association logic

User Story 5:
Title: Cover Security Rules with Automated Tests
User Story: As a developer, I want automated tests for security rules so that regressions are prevented.
Acceptance Criteria in Gherkin:
Scenario: Security test coverage
  Given the test suite
  When I run security tests
  Then unauthorized requests return 401 and forbidden actions return 403
Additional Details:
  Priority: High
  Story Points: 2
  Dependencies: E01, E02
  Notes: Use JUnit/Spring Test
