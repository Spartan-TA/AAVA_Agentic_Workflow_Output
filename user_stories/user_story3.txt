Title: Employee Master Data - CRUD API

User Story: As an HR user, I want to create, read, update, and delete employee records so that employee data is accurately maintained.

Acceptance Criteria:
Scenario: Create Employee
Given valid employee data
When I POST to /employees
Then a new employee is created with a unique badgeId

Scenario: Update Employee
Given an existing employee
When I PUT/PATCH to /employees/{id}
Then the employee data is updated

Scenario: Delete Employee
Given an employee record
When I DELETE /employees/{id}
Then the employee is soft-deleted

Scenario: List Employees
Given multiple employee records
When I GET /employees with pagination and filtering
Then I see a paginated, filtered list

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: E01
- Notes: OpenAPI schemas with examples; badgeId uniqueness enforced
