### Epic E01: Project Scaffolding & Domain Setup

**User Story 1**
Title: Initialize Spring Boot Project Structure
User Story: As a developer I want to initialize a Spring Boot project with Maven So that I have a standardized foundation for all modules
Acceptance Criteria:
Scenario: Project initialization
Given I have cloned the repository
When I run `mvn clean install`
Then the project builds successfully and runs on port 8080
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: None
- Notes: README must include build/run steps

**User Story 2**
Title: Configure Core Domain Packages
User Story: As a developer I want to set up base packages for employee, scheduling, attendance, and safety modules So that code is organized and maintainable
Acceptance Criteria:
Scenario: Base package structure
Given the project is initialized
When I open the source directory
Then I see separate packages for employee, scheduling, attendance, and safety
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Follows company package naming conventions

**User Story 3**
Title: Enable Database Migration Tool
User Story: As a developer I want to add Flyway or Liquibase for database migrations So that schema changes are versioned and repeatable
Acceptance Criteria:
Scenario: Baseline migration
Given the application starts
When Flyway/Liquibase runs
Then the baseline migration is applied without errors
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Baseline migration must create initial tables

**User Story 4**
Title: Enable Actuator Health Endpoint
User Story: As a DevOps engineer I want to enable the Actuator health endpoint So that I can monitor application health
Acceptance Criteria:
Scenario: Health endpoint
Given the application is running
When I GET /actuator/health
Then the response is 200 and status is UP
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Health endpoint must be documented in README
