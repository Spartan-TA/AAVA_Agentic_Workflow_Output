### E14 - Audit Trail & Compliance

**User Story 1**
Title: Log All Sensitive Changes
User Story: As a compliance officer I want every create, update, or delete of sensitive data to be logged So that I can audit system activity.
Acceptance Criteria:
Scenario: Audit log entry
Given a sensitive change occurs
When I review the audit log
Then the actor, timestamp, and before/after values are recorded
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E03
- Notes: Applies to PII, schedules, approvals, payroll

**User Story 2**
Title: Store Audit Logs in Tamper-Evident Table
User Story: As a system I want audit logs stored in an immutable, tamper-evident table So that integrity is ensured.
Acceptance Criteria:
Scenario: Tamper-evident storage
Given audit logs are written
When I attempt to modify them
Then the system prevents changes
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E14-1
- Notes: Use append-only storage

**User Story 3**
Title: Export Audit Logs by Date, User, or Entity
User Story: As an auditor I want to export audit logs filtered by date, user, or entity So that I can investigate incidents.
Acceptance Criteria:
Scenario: Audit log export
Given audit logs exist
When I apply filters and export
Then only matching records are included
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E14-1
- Notes: Support CSV export

**User Story 4**
Title: Test Coverage for Audit Logging
User Story: As a QA engineer I want automated tests to validate audit log coverage So that no sensitive change goes unlogged.
Acceptance Criteria:
Scenario: Audit log tests
Given the test suite runs
When sensitive changes are made
Then audit logs are created for each
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E14-1
- Notes: Cover all relevant entities
