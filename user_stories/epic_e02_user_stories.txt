Epic E02: Employee Master Data (CRUD)

---

User Story 2.1: Create Employee Entity and Repository

Title: Create Employee Entity and Repository

User Story: As a developer, I want to define the Employee entity and repository so that employee data can be persisted.

Acceptance Criteria:

Scenario: Employee entity includes all required fields
Given the codebase
When I check the Employee entity
Then it includes name, badgeId, role, department, shiftGroup, hireDate, status

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Foundation for CRUD.

User Story 2.2: Implement Employee CRUD APIs

Title: Implement Employee CRUD APIs

User Story: As an HR user, I want to create, read, update, and delete employee records via API so that employee data is managed efficiently.

Acceptance Criteria:

Scenario: All CRUD operations work correctly
Given the API
When I POST/GET/PUT/PATCH/DELETE /employees
Then the correct operations are performed

Scenario: BadgeId uniqueness enforced
Given a badgeId
When I create an employee
Then the badgeId must be unique

Scenario: Soft delete supported
Given a DELETE request
When I delete an employee
Then the record is soft-deleted

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: E02.1
- Notes: Core CRUD.
