### Epic E02: Employee Master Data (CRUD)

**User Story 1: Create Employee Entity and Repository**
User Story: As a developer I want to create an Employee entity with fields (name, badgeId, role, department, shiftGroup, hireDate, status) so that employee records are stored in the database.
Acceptance Criteria:
Scenario: Employee entity creation
Given the database is set up
When I create a new employee record
Then all required fields are persisted
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Use JPA annotations

**User Story 2: Implement Employee CRUD APIs**
User Story: As an HR user I want to create, read, update, and delete employee records via REST APIs so that employee data is managed efficiently.
Acceptance Criteria:
Scenario: CRUD operations
Given valid employee data
When I call POST/GET/PUT/PATCH/DELETE /employees
Then the appropriate action is performed and response is returned
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01, E02
- Notes: Follow OpenAPI schema

**User Story 3: Enforce Unique badgeId**
User Story: As a developer I want to enforce unique badgeId for employees so that duplicate records are prevented.
Acceptance Criteria:
Scenario: Duplicate badgeId prevention
Given an existing badgeId
When I try to create another employee with the same badgeId
Then the API returns a validation error
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E02
- Notes: Add DB unique constraint

**User Story 4: Support Soft-Delete for Employees**
User Story: As an HR user I want to soft-delete employee records so that historical data is retained.
Acceptance Criteria:
Scenario: Soft-delete operation
Given an active employee record
When I delete the employee
Then the status is updated to 'deleted' and record is excluded from active queries
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02
- Notes: Do not physically remove from DB

**User Story 5: Implement Pagination and Filtering**
User Story: As an HR user I want to paginate and filter employee records so that I can efficiently browse large datasets.
Acceptance Criteria:
Scenario: Paginated and filtered results
Given multiple employee records
When I request a paginated and filtered list
Then only matching records are returned with pagination metadata
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02
- Notes: Support filtering by department, status, etc.
