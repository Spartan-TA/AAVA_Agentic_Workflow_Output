## Epic E02: Employee Master Data (CRUD)

### User Story 1: Create Employee Record
**User Story:**  
As an HR user, I want to create a new employee record with all required fields so that employee data is centrally managed.

**Acceptance Criteria (Gherkin):**
```
Given valid employee data (name, badgeId, role, department, shiftGroup, hireDate, status)
When I POST to /employees
Then a new employee is created with a unique badgeId

Given an existing badgeId
When I try to create another employee with the same badgeId
Then the request is rejected with a uniqueness error
```

**Additional Details:**  
Priority: High  
Story Points: 3  
Dependencies: Project scaffolding  
Notes: badgeId must be unique.

---

### User Story 2: Retrieve Employee Records with Filtering and Pagination
**User Story:**  
As an HR user, I want to retrieve employee records with pagination and filtering so that I can efficiently browse and search employees.

**Acceptance Criteria (Gherkin):**
```
Given multiple employee records exist
When I GET /employees?page=1&size=10
Then I receive a paginated list of employees

Given employees in different departments
When I filter by department
Then only employees in that department are returned
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: Employee CRUD  
Notes: Filtering by role, department, status.

---

### User Story 3: Update Employee Record
**User Story:**  
As an HR user, I want to update employee details so that records remain accurate.

**Acceptance Criteria (Gherkin):**
```
Given an existing employee
When I PATCH /employees/{id} with updated data
Then the employee record is updated

Given a non-existent employee ID
When I PATCH /employees/{id}
Then I receive a 404 error
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: Employee CRUD  
Notes: PATCH and PUT supported.

---

### User Story 4: Soft Delete Employee Record
**User Story:**  
As an HR user, I want to soft-delete employee records so that historical data is preserved.

**Acceptance Criteria (Gherkin):**
```
Given an existing employee
When I DELETE /employees/{id}
Then the employee is marked as deleted but not removed from the database

Given a deleted employee
When I GET /employees
Then the deleted employee is not shown by default
```

**Additional Details:**  
Priority: High  
Story Points: 2  
Dependencies: Employee CRUD  
Notes: Soft-delete flag.

---

### User Story 5: OpenAPI Schema Documentation
**User Story:**  
As a developer, I want OpenAPI schemas with examples for employee endpoints so that API consumers understand request/response formats.

**Acceptance Criteria (Gherkin):**
```
Given the API documentation endpoint
When I access it
Then I see schemas for all employee endpoints with example payloads
```

**Additional Details:**  
Priority: High  
Story Points: 1  
Dependencies: Employee CRUD  
Notes: Use Swagger/OpenAPI.
