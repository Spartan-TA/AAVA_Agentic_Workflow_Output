### Epic E02: Employee Master Data (CRUD)

#### User Story 1: Create Employee Record
- **Title:** Employee Creation API
- **User Story:** As an HR user, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centralized.
- **Acceptance Criteria:**
  ```
  Scenario: Create employee
    Given valid employee details
    When I POST to /employees
    Then a new employee is created and badgeId is unique
  ```
- **Priority:** High
- **Story Points:** 3
- **Dependencies:** E01
- **Notes:** Enforce badgeId uniqueness.

#### User Story 2: Retrieve Employee Records
- **Title:** Employee Retrieval API
- **User Story:** As an HR user, I want to retrieve employee records with pagination and filtering so that I can find employees efficiently.
- **Acceptance Criteria:**
  ```
  Scenario: Get employees with filters
    Given multiple employees exist
    When I GET /employees?department=Shipping&page=1
    Then I receive a paginated, filtered list of employees
  ```
- **Priority:** High
- **Story Points:** 2
- **Dependencies:** E01
- **Notes:** Supports OpenAPI schemas with examples.

#### User Story 3: Update Employee Details
- **Title:** Employee Update API
- **User Story:** As an HR user, I want to update employee details so that records remain accurate.
- **Acceptance Criteria:**
  ```
  Scenario: Update employee
    Given an existing employee
    When I PUT /employees/{id} with new details
    Then the employee record is updated
  ```
- **Priority:** High
- **Story Points:** 2
- **Dependencies:** E01
- **Notes:** PATCH for partial updates.

#### User Story 4: Soft-Delete Employee
- **Title:** Employee Soft-Delete API
- **User Story:** As an HR user, I want to soft-delete employee records so that terminated employees are not lost but excluded from active lists.
- **Acceptance Criteria:**
  ```
  Scenario: Soft-delete employee
    Given an employee exists
    When I DELETE /employees/{id}
    Then the employee is marked as deleted but not removed from the database
  ```
- **Priority:** High
- **Story Points:** 2
- **Dependencies:** E01
- **Notes:** Deleted employees excluded from active queries.
