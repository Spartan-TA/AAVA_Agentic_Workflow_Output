### E02: Employee Master Data (CRUD)

#### 1. Title: Create Employee API (POST)
User Story: As an HR user I want to add new employees with all required fields So that employee records are up to date
Acceptance Criteria:
Scenario: Successful creation
Given I provide valid employee data
When I POST to `/employees`
Then a new employee is created with a unique badgeId

Scenario: Duplicate badgeId
Given an employee with badgeId X exists
When I try to create another with badgeId X
Then I receive a 409 Conflict error

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: Validate required fields

---

#### 2. Title: Retrieve Employee List (GET)
User Story: As an HR user I want to view a paginated, filterable list of employees So that I can easily find and manage records
Acceptance Criteria:
Scenario: Paginated results
Given there are more than 20 employees
When I GET `/employees?page=1&size=20`
Then I receive 20 employees and pagination metadata

Scenario: Filter by department
Given employees in multiple departments
When I filter by `department=Shipping`
Then only employees in Shipping are returned

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: Support filtering by role, status, shiftGroup

---

#### 3. Title: Update Employee Details (PUT/PATCH)
User Story: As an HR user I want to update employee details So that records remain accurate
Acceptance Criteria:
Scenario: Update name or department
Given an employee exists
When I PATCH `/employees/{id}` with new data
Then the changes are saved and reflected in GET requests

Scenario: Invalid update
Given an invalid field value
When I PATCH the employee
Then I receive a 400 Bad Request

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Support partial updates

---

#### 4. Title: Soft Delete Employee
User Story: As an HR user I want to soft-delete employees So that historical data is preserved
Acceptance Criteria:
Scenario: Soft delete
Given an active employee
When I DELETE `/employees/{id}`
Then the employee status is set to "inactive" and not returned in active lists

Scenario: Restore deleted employee
Given a soft-deleted employee
When I PATCH `/employees/{id}` with status "active"
Then the employee is restored

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: No hard deletes

---

#### 5. Title: Employee OpenAPI Documentation
User Story: As a developer I want OpenAPI docs for employee endpoints So that integration is straightforward
Acceptance Criteria:
Scenario: OpenAPI docs available
Given the application is running
When I access `/swagger-ui`
Then I see all employee endpoints with request/response examples

Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Keep docs up to date
