## E02 - Employee Master Data (CRUD)

### Story 1: Create Employee API (POST)
- **User Story:** As an HR user, I want to create new employee records so that new hires are registered in the system.
- **Acceptance Criteria:**
    ```
    Given valid employee data (name, badgeId, role, department, shiftGroup, hireDate, status)
    When I POST to '/employees'
    Then a new employee is created with a unique badgeId

    Given an existing badgeId
    When I attempt to create another employee with the same badgeId
    Then the request is rejected with a validation error
    ```
- **Additional Details:**  
    Priority: High  
    Story Points: 5  
    Dependencies: E01  
    Notes: badgeId must be unique.

### Story 2: Retrieve Employee List (GET)
- **User Story:** As an HR user, I want to retrieve a paginated and filterable list of employees so that I can manage employee records efficiently.
- **Acceptance Criteria:**
    ```
    Given multiple employees exist
    When I GET '/employees?department=Shipping&page=1&size=20'
    Then I receive a paginated list filtered by department

    Given no filters
    When I GET '/employees'
    Then I receive all employees paginated by default settings
    ```
- **Additional Details:**  
    Priority: High  
    Story Points: 3  
    Dependencies: E01  
    Notes: Support filtering by department, role, status.

### Story 3: Update Employee Details (PUT/PATCH)
- **User Story:** As an HR user, I want to update employee details so that records remain current.
- **Acceptance Criteria:**
    ```
    Given an existing employee
    When I PUT or PATCH '/employees/{id}' with valid changes
    Then the employee record is updated

    Given an invalid field (e.g., duplicate badgeId)
    When I update the employee
    Then the request is rejected with a validation error
    ```
- **Additional Details:**  
    Priority: High  
    Story Points: 3  
    Dependencies: E01  
    Notes: Partial updates via PATCH.

### Story 4: Soft-Delete Employee
- **User Story:** As an HR user, I want to soft-delete employees so that terminated employees are not lost but excluded from active lists.
- **Acceptance Criteria:**
    ```
    Given an existing employee
    When I DELETE '/employees/{id}'
    Then the employee's status is set to 'inactive' and not removed from the database

    Given a soft-deleted employee
    When I GET '/employees?status=active'
    Then the employee does not appear in the results
    ```
- **Additional Details:**  
    Priority: High  
    Story Points: 2  
    Dependencies: E01  
    Notes: No hard deletes.

### Story 5: OpenAPI Documentation for Employee APIs
- **User Story:** As a Developer, I want OpenAPI schemas with examples for employee endpoints so that integration is easy and clear.
- **Acceptance Criteria:**
    ```
    Given the API documentation
    When I view the OpenAPI spec
    Then all employee endpoints are documented with request/response examples
    ```
- **Additional Details:**  
    Priority: Medium  
    Story Points: 2  
    Dependencies: E01  
    Notes: Use Swagger UI.
