Title: Log Sensitive Changes with Actor and Timestamp

User Story: As a compliance officer I want all sensitive changes to be logged with actor and timestamp so that audit and forensic analysis are possible

Acceptance Criteria:
Scenario: Logging a change
Given a create, update, or delete occurs on sensitive data
When the action is performed
Then the log records actor, timestamp, before/after values

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: RBAC
- Notes: Applies to employee PII, schedules, approvals, payroll

Title: Store Audit Logs in Immutable Table

User Story: As a system administrator I want audit logs stored in an immutable table so that tampering is prevented

Acceptance Criteria:
Scenario: Storing audit logs
Given a log entry is created
When it is saved
Then it cannot be modified or deleted

Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: Audit logging
- Notes: Must support export by date/user/entity

---

Title: Export Audit Logs by Date, User, or Entity

User Story: As a compliance officer I want to export audit logs by date, user, or entity so that I can respond to audit requests

Acceptance Criteria:
Scenario: Exporting audit logs
Given audit logs exist for a period or user
When I request an export
Then the system generates a file with all matching log entries

Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: Audit logging
- Notes: Export must be covered by automated tests

---

Title: Validate Audit Logging Coverage with Automated Tests

User Story: As a QA engineer I want automated tests to validate audit logging coverage so that no sensitive changes go unlogged

Acceptance Criteria:
Scenario: Test audit logging
Given a test suite runs
When sensitive changes are made
Then audit log entries are created and verified

Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: Audit logging
- Notes: Coverage must be 100% for sensitive actions
