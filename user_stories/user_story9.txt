### E09 - Equipment & Asset Assignment

**User Story 1:**
Title: Asset Registry CRUD
User Story: As an asset manager, I want to add, update, and remove assets so that inventory is accurate.
Acceptance Criteria:
Scenario: Create asset
  Given asset data
  When I POST /assets
  Then the asset is created
Scenario: Update asset
  Given an existing asset
  When I PUT /assets/{id}
  Then the asset is updated
Scenario: Delete asset
  Given an existing asset
  When I DELETE /assets/{id}
  Then the asset is deleted
Additional Details:
- Priority: Medium
- Story Points: 3
- Dependencies: E02, E03, E07
- Notes: Asset management

**User Story 2:**
Title: Asset Check-In/Check-Out
User Story: As a worker, I want to check out and return assets so that usage is tracked.
Acceptance Criteria:
Scenario: Check out asset
  Given a valid asset and employee
  When I check out an asset
  Then the assignment is recorded
Scenario: Check in asset
  Given a checked-out asset
  When I check it in
  Then the return is recorded
Additional Details:
- Priority: Medium
- Story Points: 3
- Dependencies: E02, E03, E07
- Notes: Usage tracking

**User Story 3:**
Title: Block Asset Use Without Valid Certification
User Story: As a supervisor, I want to prevent asset checkout if the employee lacks required certification.
Acceptance Criteria:
Scenario: Block checkout without certification
  Given an employee without valid cert
  When I try to check out a restricted asset
  Then the system blocks the action
Additional Details:
- Priority: Medium
- Story Points: 2
- Dependencies: E02, E03, E07
- Notes: Safety enforcement

**User Story 4:**
Title: Asset and Employee History Log
User Story: As an auditor, I want to view the history of asset assignments and returns per asset and employee.
Acceptance Criteria:
Scenario: View asset history
  Given an asset or employee
  When I view the history
  Then all check-in/out events are listed chronologically
Additional Details:
- Priority: Medium
- Story Points: 2
- Dependencies: E02, E03, E07
- Notes: Auditability

**User Story 5:**
Title: Overdue Asset Return Reports
User Story: As an asset manager, I want to generate reports of overdue asset returns so that follow-up actions can be taken.
Acceptance Criteria:
Scenario: Generate overdue report
  Given asset assignment data
  When I request an overdue report
  Then all overdue assets are listed with assigned employees
Additional Details:
- Priority: Medium
- Story Points: 1
- Dependencies: E02, E03, E07
- Notes: Accountability
