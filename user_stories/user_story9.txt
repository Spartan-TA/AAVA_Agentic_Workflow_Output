### Epic E09: Equipment & Asset Assignment

**User Story 1: Asset Registry CRUD**
- Title: Manage Asset Registry
- User Story: As a System Admin, I want to create, update, and delete asset records so that equipment inventory is accurate.
- Acceptance Criteria:
  ```
  Given the admin is authenticated,
  When they perform CRUD operations on assets,
  Then the asset registry is updated accordingly.
  ```
- Additional Details: Priority: Medium, Story Points: 2, Dependencies: E02, E03, E07, Notes: Scanners, forklifts, PPE.

**User Story 2: Assign Assets to Employees**
- Title: Assign Equipment to Employees
- User Story: As a Supervisor, I want to assign and track equipment checkout/return so that accountability is maintained.
- Acceptance Criteria:
  ```
  Given a SUPERVISOR is authenticated,
  When they assign an asset to an employee,
  Then the checkout is recorded.

  Given an asset is returned,
  When the return is processed,
  Then the asset status is updated.
  ```
- Additional Details: Priority: Medium, Story Points: 2, Dependencies: E02, E03, E07, Notes: Checkout/return workflow.

**User Story 3: Block Asset Use if Certification Missing**
- Title: Block Asset Use for Unqualified Employees
- User Story: As a Supervisor, I want to prevent asset assignment if required certifications are missing so that safety is enforced.
- Acceptance Criteria:
  ```
  Given an employee lacks certification,
  When asset assignment is attempted,
  Then the system blocks the assignment and notifies the supervisor.
  ```
- Additional Details: Priority: Medium, Story Points: 2, Dependencies: E02, E03, E07, Notes: Certification check.

**User Story 4: Track Asset Condition**
- Title: Track Asset Condition State
- User Story: As a Supervisor, I want to record asset condition during check-in/out so that maintenance needs are tracked.
- Acceptance Criteria:
  ```
  Given an asset is checked in/out,
  When condition is recorded,
  Then the asset record is updated with condition state.
  ```
- Additional Details: Priority: Medium, Story Points: 1, Dependencies: E02, E03, E07, Notes: Maintenance tracking.

**User Story 5: Asset History Log**
- Title: View Asset Assignment History
- User Story: As a Supervisor, I want to view the history of asset assignments per employee and asset so that usage is traceable.
- Acceptance Criteria:
  ```
  Given an asset or employee is selected,
  When history is requested,
  Then a log of all check-in/out events is displayed.
  ```
- Additional Details: Priority: Medium, Story Points: 1, Dependencies: E02, E03, E07, Notes: Audit log.

**User Story 6: Overdue Asset Return Report**
- Title: Report Overdue Asset Returns
- User Story: As a Supervisor, I want to generate reports of overdue asset returns so that follow-up actions can be taken.
- Acceptance Criteria:

### Epic E11: Payroll Export Integration

**User Story 1: Generate Payroll-Ready Export**
- Title: Generate Payroll Export File
- User Story: As a Payroll Admin, I want to generate payroll-ready files from attendance and leave data so that payroll runs are accurate.
- Acceptance Criteria:
  ```
  Given approved attendance and leave data,
  When export is requested,
  Then a file matching the payroll provider schema is generated.
  ```
- Additional Details: Priority: High, Story Points: 3, Dependencies: E04, E06, Notes: Schema mapping.

**User Story 2: Secure Delivery of Payroll Files**
- Title: Secure Payroll File Delivery
- User Story: As a Payroll Admin, I want payroll files delivered securely via SFTP or API so that data is protected.
- Acceptance Criteria:
  ```
  Given a payroll file is generated,
  When delivery is initiated,
  Then the file is sent via SFTP or API with encryption.
  ```
- Additional Details: Priority: High, Story Points: 2, Dependencies: E04, E06, Notes: Secure protocols.

**User Story 3: Retry Failed Deliveries**
- Title: Retry Failed Payroll Deliveries
- User Story: As a Payroll Admin, I want failed deliveries retried with backoff so that exports are reliably delivered.
- Acceptance Criteria:
  ```
  Given a delivery fails,
  When the system retries,
  Then retries are performed with exponential backoff until success or max attempts.
  ```
- Additional Details: Priority: High, Story Points: 2, Dependencies: E04, E06, Notes: Error handling.

**User Story 4: Audit Log for Payroll Exports**
- Title: Audit Payroll Export Actions
- User Story: As a Compliance Officer, I want an audit log for every payroll export so that actions are traceable.
- Acceptance Criteria:
  ```
  Given a payroll export is performed,
  When the action completes,
  Then an audit entry is generated with actor, timestamp, and status.
  ```
- Additional Details: Priority: High, Story Points: 1, Dependencies: E04, E06, Notes: Compliance tracking.

**User Story 5: Reconcile Payroll Totals**
- Title: Reconcile Payroll Export Totals
- User Story: As a Payroll Admin, I want to reconcile payroll export totals with attendance and leave reports so that errors are detected.
- Acceptance Criteria:
  ```
  Given payroll export and reports exist,
  When reconciliation is performed,
  Then totals match and discrepancies are flagged.
  ```
- Additional Details: Priority: High, Story Points: 2, Dependencies: E04, E06, Notes: Validation logic.
