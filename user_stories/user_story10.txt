### Epic E14: Audit Trail & Compliance

**User Story 1: Log Sensitive Changes**
- Title: Log Sensitive Data Changes
- User Story: As a Compliance Officer, I want all changes to sensitive data logged with actor and timestamp so that audits are possible.
- Acceptance Criteria:
  ```
  Given a create/update/delete action on sensitive data,
  When the action occurs,
  Then an audit log entry is created with actor, timestamp, before/after values.
  ```
- Additional Details: Priority: High, Story Points: 2, Dependencies: E03, Notes: PII, schedules, approvals, payroll.

**User Story 2: Immutable Audit Log Table**
- Title: Store Audit Logs in Immutable Table
- User Story: As a System Admin, I want audit logs stored in an immutable table so that tampering is prevented.
- Acceptance Criteria:
  ```
  Given audit logs are stored,
  When an attempt to modify is made,
  Then the system prevents changes to existing entries.
  ```
- Additional Details: Priority: High, Story Points: 2, Dependencies: E03, Notes: Tamper-evident storage.

**User Story 3: Export Audit Logs**
- Title: Export Audit Logs by Date/User/Entity
- User Story: As a Compliance Officer, I want to export audit logs by date, user, or entity so that investigations are efficient.
- Acceptance Criteria:
  ```
  Given audit logs exist,
  When export is requested with filters,
  Then a report is generated with matching entries.
  ```
- Additional Details: Priority: High, Story Points: 1, Dependencies: E03, Notes: Export format.

**User Story 4: Automated Audit Coverage Tests**
- Title: Automated Audit Coverage Tests
- User Story: As a Developer, I want tests to validate audit coverage so that no sensitive changes go unlogged.
- Acceptance Criteria:
  ```
  Given the test suite,
  When tests are run,
  Then all sensitive actions are verified to generate audit logs.
  ```
- Additional Details: Priority: High, Story Points: 1, Dependencies: E03, Notes: Regression coverage.
