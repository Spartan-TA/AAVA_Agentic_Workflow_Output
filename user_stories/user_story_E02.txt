### E02: Employee Master Data (CRUD)

**User Story 1**
- **Title:** Create Employee Record
- **User Story:** As an HR user, I want to create new employee records so that employee data is centrally managed.
- **Acceptance Criteria:**
    - Scenario: Employee creation
      - Given I have HR role
      - When I POST valid employee data to `/employees`
      - Then a new employee is created with a unique badgeId
- **Additional Details:** Priority: High, Story Points: 3, Dependencies: E01, Notes: Validate required fields.

**User Story 2**
- **Title:** Retrieve Employee List with Filtering
- **User Story:** As an HR user, I want to view and filter employee records so that I can quickly find relevant employees.
- **Acceptance Criteria:**
    - Scenario: Filter by department
      - Given employees exist in multiple departments
      - When I GET `/employees?department=Shipping`
      - Then only employees in Shipping are returned
    - Scenario: Pagination
      - Given more than 50 employees
      - When I GET `/employees?page=2&size=20`
      - Then I receive the correct page of results
- **Additional Details:** Priority: High, Story Points: 3, Dependencies: E01, Notes: Support filtering by role, status.

**User Story 3**
- **Title:** Update Employee Details
- **User Story:** As an HR user, I want to update employee information so that records remain accurate.
- **Acceptance Criteria:**
    - Scenario: Update name and department
      - Given an employee exists
      - When I PATCH `/employees/{id}` with new data
      - Then the employee record is updated
- **Additional Details:** Priority: High, Story Points: 2, Dependencies: User Story 1, Notes: PATCH and PUT supported.

**User Story 4**
- **Title:** Soft-Delete Employee
- **User Story:** As an HR user, I want to soft-delete employees so that historical data is preserved.
- **Acceptance Criteria:**
    - Scenario: Soft-delete action
      - Given an active employee
      - When I DELETE `/employees/{id}`
      - Then the employee status is set to "inactive" and not removed from DB
- **Additional Details:** Priority: High, Story Points: 2, Dependencies: User Story 1, Notes: No hard deletes.

**User Story 5**
- **Title:** Enforce Unique Badge ID
- **User Story:** As an HR user, I want badge IDs to be unique so that each employee is uniquely identified.
- **Acceptance Criteria:**
    - Scenario: Duplicate badgeId
      - Given an employee with badgeId "12345" exists
      - When I try to create another with badgeId "12345"
      - Then I receive a validation error
- **Additional Details:** Priority: High, Story Points: 1, Dependencies: User Story 1, Notes: Enforced at DB and API.

**User Story 6**
- **Title:** OpenAPI Documentation for Employee APIs
- **User Story:** As a developer, I want OpenAPI schemas with examples for employee endpoints so that integration is straightforward.
- **Acceptance Criteria:**
    - Scenario: OpenAPI docs available
      - Given the app is running
      - When I access `/swagger-ui.html`
      - Then I see all employee endpoints with request/response examples
- **Additional Details:** Priority: High, Story Points: 1, Dependencies: All CRUD endpoints, Notes: Keep docs up to date.
