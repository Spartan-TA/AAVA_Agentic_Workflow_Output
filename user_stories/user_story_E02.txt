### E02 - Employee Master Data (CRUD)

**User Story 1:**
- Title: Create Employee API Endpoints
- User Story: As an HR user, I want to create, read, update, and delete employee records so that employee data is managed centrally.
- Acceptance Criteria:
  - Scenario: Create employee
    - Given valid employee data
    - When I POST to `/employees`
    - Then the employee is created and returned
  - Scenario: Update employee
    - Given an existing employee
    - When I PUT/PATCH to `/employees/{id}`
    - Then the employee data is updated
  - Scenario: Delete employee
    - Given an existing employee
    - When I DELETE `/employees/{id}`
    - Then the employee is soft-deleted
- Additional Details: Priority: High, Story Points: 5, Dependencies: E01

**User Story 2:**
- Title: Enforce Unique Badge ID
- User Story: As an HR user, I want badge IDs to be unique so that each employee is uniquely identifiable.
- Acceptance Criteria:
  - Scenario: Duplicate badgeId rejected
    - Given an existing badgeId
    - When I try to create another employee with the same badgeId
    - Then the request is rejected with a validation error
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01

**User Story 3:**
- Title: Support Pagination and Filtering
- User Story: As an HR user, I want to paginate and filter employee lists so that I can efficiently find records.
- Acceptance Criteria:
  - Scenario: Paginated results
    - Given many employees
    - When I GET `/employees?page=1&size=20`
    - Then I receive 20 employees and pagination metadata
  - Scenario: Filter by department
    - Given employees in multiple departments
    - When I GET `/employees?department=Shipping`
    - Then only employees in Shipping are returned
- Additional Details: Priority: High, Story Points: 3, Dependencies: E01

**User Story 4:**
- Title: Provide OpenAPI Schemas
- User Story: As a developer, I want OpenAPI documentation with examples for employee endpoints so that integration is easy.
- Acceptance Criteria:
  - Scenario: OpenAPI docs available
    - Given the application is running
    - When I access `/swagger-ui`
    - Then employee endpoints are documented with request/response examples
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01
