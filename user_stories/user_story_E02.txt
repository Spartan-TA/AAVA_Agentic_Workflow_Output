### E02 - Employee Master Data (CRUD)

**User Story 2.1: Create Employee API**
User Story: As an HR user I want to create new employee records via API So that I can onboard staff efficiently.

Acceptance Criteria:
Scenario: Employee creation
Given valid employee data
When I POST to /employees
Then a new employee is created with a unique badgeId

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: badgeId must be unique.

---

**User Story 2.2: Retrieve Employee List with Filtering**
User Story: As an HR user I want to retrieve a paginated and filtered list of employees So that I can manage large workforces easily.

Acceptance Criteria:
Scenario: Employee list retrieval
Given multiple employees exist
When I GET /employees with filters
Then I receive a paginated, filtered list matching criteria

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E02.1
- Notes: Filtering by department, status, role.

---

**User Story 2.3: Update Employee Details**
User Story: As an HR user I want to update employee details So that records remain accurate.

Acceptance Criteria:
Scenario: Employee update
Given an existing employee
When I PATCH /employees/{id} with new data
Then the employee record is updated

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02.1
- Notes: Only allowed fields can be updated.

---

**User Story 2.4: Soft Delete Employee**
User Story: As an HR user I want to soft-delete employee records So that historical data is preserved.

Acceptance Criteria:
Scenario: Employee soft-delete
Given an active employee
When I DELETE /employees/{id}
Then the employee status is set to inactive, not removed from DB

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02.1
- Notes: Soft-deleted employees are excluded from active lists.

---

**User Story 2.5: OpenAPI Schema Documentation**
User Story: As a developer I want OpenAPI schemas with examples for employee APIs So that integration is straightforward.

Acceptance Criteria:
Scenario: OpenAPI docs
Given the API is deployed
When I access the OpenAPI docs
Then all employee endpoints are documented with request/response examples

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02.1
- Notes: Must include all CRUD endpoints.
