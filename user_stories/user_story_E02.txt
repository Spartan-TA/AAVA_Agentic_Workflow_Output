[E02] Employee Master Data (CRUD)

User Story 1
Title: Create Employee Entity and Repository

User Story: As a developer, I want to define the Employee entity and repository so that employee data can be persisted.

Acceptance Criteria:
Scenario: Employee entity created
Given the domain model
When I inspect the code
Then Employee has fields: name, badgeId, role, department, shiftGroup, hireDate, status

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: badgeId must be unique

User Story 2
Title: Implement Employee CRUD REST APIs

User Story: As an HR user, I want to create, read, update, and delete employee records via REST APIs so that employee data is manageable.

Acceptance Criteria:
Scenario: CRUD endpoints available
Given the API is running
When I POST/GET/PUT/PATCH/DELETE /employees
Then the operations succeed with correct validation

Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E02-1
- Notes: Soft-delete supported

User Story 3
Title: Add Pagination and Filtering to Employee List

User Story: As an HR user, I want to paginate and filter employee lists so that I can efficiently find records.

Acceptance Criteria:
Scenario: List employees with filters
Given a large employee dataset
When I GET /employees with filters and pagination
Then I receive the correct subset of employees

Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02-2
- Notes: Filter by department, status, role

User Story 4
Title: Enforce Unique Badge ID

User Story: As a system, I want to enforce unique badgeId for employees so that duplicate entries are prevented.

Acceptance Criteria:
Scenario: Duplicate badgeId rejected
Given an existing employee with badgeId X
When I try to create another with badgeId X
Then the request is rejected with a validation error

Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E02-1
- Notes: badgeId is indexed
