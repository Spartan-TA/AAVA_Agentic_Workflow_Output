### E02: Employee Master Data (CRUD)

**User Story 1**
Title: Create Employee Records
User Story: As an HR I want to create new employee records So that all staff are registered in the system.
Acceptance Criteria:
Scenario: Valid employee creation
  Given I provide all required fields
  When I POST to /employees
  Then a new employee is created with a unique badgeId
Scenario: Duplicate badgeId rejected
  Given an employee with badgeId X exists
  When I try to create another with badgeId X
  Then the request is rejected with a validation error
Scenario: OpenAPI schema available
  Given I access the API docs
  When I view /employees
  Then I see request/response examples
Additional Details:
Priority: High
Story Points: 5
Dependencies: E01
Notes: badgeId must be unique.

**User Story 2**
Title: Update Employee Details
User Story: As an HR I want to update employee information So that records remain current.
Acceptance Criteria:
Scenario: Update succeeds
  Given an employee exists
  When I PATCH their record
  Then the changes are saved
Scenario: Invalid data rejected
  Given I provide invalid data
  When I PATCH
  Then I receive a validation error
Scenario: Soft-delete supported
  Given an employee is terminated
  When I DELETE their record
  Then the record is soft-deleted, not removed
Additional Details:
Priority: High
Story Points: 3
Dependencies: E01
Notes: Soft-delete for auditability.

**User Story 3**
Title: List and Filter Employees
User Story: As an ADMIN I want to list, paginate, and filter employees So that I can efficiently manage large staff lists.
Acceptance Criteria:
Scenario: Pagination works
  Given >20 employees
  When I GET /employees?page=2
  Then I see the correct subset
Scenario: Filtering by department
  Given employees in multiple departments
  When I filter by department
  Then only matching employees are returned
Additional Details:
Priority: High
Story Points: 2
Dependencies: E01
Notes: Filtering by role, status, department.
