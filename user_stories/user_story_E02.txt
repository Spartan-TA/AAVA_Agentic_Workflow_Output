### Epic E02 - Employee Master Data (CRUD)

**User Story 1**
- Title: Employee Creation API
- User Story: As an HR user, I want to create new employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centrally managed.
- Acceptance Criteria:
  - Given valid employee data,
    When I POST to `/employees`,
    Then a new employee is created and badgeId is unique.
  - Given a duplicate badgeId,
    When I POST to `/employees`,
    Then I receive a validation error.
- Additional Details: Priority: High, Story Points: 3, Dependencies: E01, Notes: Unique badgeId enforced.

**User Story 2**
- Title: Employee Retrieval and Filtering
- User Story: As an HR user, I want to retrieve and filter employee records so that I can view and manage employee lists efficiently.
- Acceptance Criteria:
  - Given multiple employees,
    When I GET `/employees?department=Shipping`,
    Then only employees in Shipping are returned.
  - Given many employees,
    When I GET `/employees?page=1&size=20`,
    Then results are paginated.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, Notes: Supports filtering and pagination.

**User Story 3**
- Title: Employee Update API
- User Story: As an HR user, I want to update employee details so that records remain current.
- Acceptance Criteria:
  - Given an existing employee,
    When I PATCH `/employees/{id}` with valid changes,
    Then the employee record is updated.
- Additional Details: Priority: High, Story Points: 2, Dependencies: E01, Notes: Supports PATCH and PUT.

**User Story 4**
- Title: Employee Deletion (Soft Delete)
- User Story: As an HR user, I want to soft-delete employee records so that historical data is retained.
- Acceptance Criteria:
  - Given an employee,
    When I DELETE `/employees/{id}`,
    Then the employee is marked as inactive but not removed from the database.
- Additional Details: Priority: High, Story Points: 1, Dependencies: E01, Notes: Soft-delete supported.

**User Story 5**
- Title: Employee API Documentation
- User Story: As a developer, I want OpenAPI schemas with examples for employee endpoints so that integration is straightforward.
- Acceptance Criteria:
  - Given the API documentation,
    When I view `/employees` endpoints,
    Then I see request/response examples.
- Additional Details: Priority: High, Story Points: 1, Dependencies: E01, Notes: Ensures API clarity.
