### E02 - Employee Master Data (CRUD)

**Title:** Create Employee Domain Model
User Story: As a developer I want to define the Employee entity with name, badgeId, role, department, shiftGroup, hireDate, and status So that employee data is standardized
Acceptance Criteria:
Scenario: Employee entity exists
Given the codebase
When I inspect the domain models
Then Employee has all required fields
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: badgeId must be unique

**Title:** Implement Employee CRUD APIs
User Story: As an HR user I want to create, read, update, and delete employee records via API So that employee data is managed efficiently
Acceptance Criteria:
Scenario: Create employee
Given valid employee data
When I POST to `/employees`
Then a new employee is created and badgeId is unique
Scenario: Soft-delete employee
Given an existing employee
When I DELETE `/employees/{id}`
Then the employee is marked as deleted, not removed
Scenario: Pagination and filtering
Given multiple employees
When I GET `/employees?department=Receiving&page=1`
Then results are filtered and paginated
Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Create Employee Domain Model
- Notes: OpenAPI schemas must include examples

**Title:** Enforce Unique Badge ID
User Story: As a developer I want to enforce unique badgeId for employees So that duplicate badge assignments are prevented
Acceptance Criteria:
Scenario: Duplicate badgeId rejected
Given an existing badgeId
When I POST a new employee with the same badgeId
Then the request fails with a validation error
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: Implement Employee CRUD APIs
- Notes: Validation at both API and DB level
