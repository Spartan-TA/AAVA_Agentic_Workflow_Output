### E02: Employee Master Data (CRUD)

**User Story 1**
Title: Create Employee API (POST)
User Story: As an HR I want to add a new employee with name, badgeId, role, department, shiftGroup, hireDate, and status So that employee records are up to date
Acceptance Criteria:
Scenario: Add new employee
Given valid employee data
When I POST to `/employees`
Then the employee is created and badgeId is unique
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: Returns 409 if badgeId exists

**User Story 2**
Title: Retrieve Employee List with Filtering
User Story: As an ADMIN I want to retrieve a paginated, filterable list of employees So that I can manage large workforces
Acceptance Criteria:
Scenario: List employees with filters
Given multiple employees exist
When I GET `/employees?department=Shipping&status=Active&page=1`
Then I receive a paginated list filtered by department and status
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Supports filtering by all fields

**User Story 3**
Title: Update Employee Details (PUT/PATCH)
User Story: As an HR I want to update employee details So that records remain accurate
Acceptance Criteria:
Scenario: Update employee
Given an existing employee
When I PUT/PATCH to `/employees/{id}` with valid data
Then the employee record is updated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Returns 404 if employee not found

**User Story 4**
Title: Soft Delete Employee
User Story: As an ADMIN I want to soft-delete employees So that historical data is preserved
Acceptance Criteria:
Scenario: Soft delete employee
Given an active employee
When I DELETE `/employees/{id}`
Then the employee status is set to "Inactive" and not removed from DB
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E01
- Notes: Soft-deleted employees excluded from active lists

**User Story 5**
Title: OpenAPI Schema with Examples
User Story: As a DEVELOPER I want OpenAPI docs with request/response examples for employee APIs So that integration is easy
Acceptance Criteria:
Scenario: View OpenAPI docs
Given the API is running
When I access `/swagger-ui.html`
Then I see employee endpoints with example payloads
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E01
- Notes: Follows company API standards
