### Epic E02: Employee Master Data (CRUD)

**User Story 1**
Title: Create Employee Record
User Story: As an HR user, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centralized.
Acceptance Criteria:
Scenario: Employee Creation
Given valid employee data
When I POST to /employees
Then a new employee record is created with a unique badgeId
Priority: High
Story Points: 3
Dependencies: E01
Notes: badgeId must be unique.

**User Story 2**
Title: Update Employee Record
User Story: As an HR user, I want to update employee details so that records remain accurate.
Acceptance Criteria:
Scenario: Employee Update
Given an existing employee
When I PUT/PATCH to /employees/{id}
Then the employee record is updated
Priority: High
Story Points: 2
Dependencies: E01
Notes: OpenAPI schemas must be updated.

**User Story 3**
Title: Delete (Soft) Employee Record
User Story: As an HR user, I want to soft-delete employee records so that historical data is preserved.
Acceptance Criteria:
Scenario: Employee Soft-Delete
Given an employee exists
When I DELETE /employees/{id}
Then the employee status is set to inactive, not removed from DB
Priority: High
Story Points: 2
Dependencies: E01
Notes: Soft-delete must be reflected in queries.

**User Story 4**
Title: List and Filter Employees
User Story: As a supervisor, I want to list and filter employees by department, role, and status so that I can manage my team efficiently.
Acceptance Criteria:
Scenario: Employee Listing
Given employees exist
When I GET /employees with filters
Then I receive a paginated, filtered list
Priority: High
Story Points: 2
Dependencies: E01
Notes: Pagination required.
