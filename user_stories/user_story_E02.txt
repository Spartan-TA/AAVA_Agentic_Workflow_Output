### E02 - Employee Master Data (CRUD)

**Title:** Create Employee Record  
User Story: As an HR user, I want to create employee records with name, badgeId, role, department, shiftGroup, hireDate, and status So that employee data is centrally managed.  
Acceptance Criteria:  
Scenario: Employee Creation  
Given valid employee details  
When I POST to /employees  
Then a new employee is created with a unique badgeId  
Additional Details:  
- Priority: High  
- Story Points: 3  
- Dependencies: Project Scaffolding  
- Notes: badgeId uniqueness enforced

---

**Title:** Update Employee Record  
User Story: As an HR user, I want to update employee information So that records stay current and accurate.  
Acceptance Criteria:  
Scenario: Employee Update  
Given an existing employee  
When I PUT/PATCH to /employees/{id}  
Then the employee record is updated  
Additional Details:  
- Priority: High  
- Story Points: 2  
- Dependencies: Create Employee Record  
- Notes: Partial updates supported

---

**Title:** Delete Employee Record (Soft Delete)  
User Story: As an HR user, I want to soft-delete employee records So that historical data is preserved but inactive employees are hidden.  
Acceptance Criteria:  
Scenario: Employee Deletion  
Given an employee record  
When I DELETE /employees/{id}  
Then the record is marked as inactive  
Additional Details:  
- Priority: High  
- Story Points: 2  
- Dependencies: Create Employee Record  
- Notes: Soft delete only, no hard delete

---

**Title:** List & Filter Employees  
User Story: As a supervisor, I want to list and filter employees by department, role, and status So that I can quickly find relevant staff.  
Acceptance Criteria:  
Scenario: Employee Listing  
Given employees exist  
When I GET /employees with filters  
Then the response is paginated and filtered  
Additional Details:  
- Priority: High  
- Story Points: 2  
- Dependencies: Create Employee Record  
- Notes: OpenAPI schema must include examples
