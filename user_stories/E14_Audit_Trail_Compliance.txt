====================================================================
Epic E14: Audit Trail & Compliance
====================================================================

User Story 1:
- Title: Centralized Audit Logging for Sensitive Changes
- User Story: As a compliance officer, I want all sensitive changes to be logged centrally so that audits are possible.
- Acceptance Criteria:
  - Given a create/update/delete, When performed, Then actor, timestamp, and before/after values are logged.
- Additional Details: Priority: High, Story Points: 5, Dependencies: E03, Notes: Tamper-evident storage.

User Story 2:
- Title: Provide Immutable Audit Log Table
- User Story: As an auditor, I want the audit log to be immutable so that records cannot be altered.
- Acceptance Criteria:
  - Given an audit entry, When queried, Then it cannot be modified or deleted.
- Additional Details: Priority: High, Story Points: 3, Dependencies: User Story 1, Notes: Enforced at DB level.

User Story 3:
- Title: Export Audit Logs by Date/User/Entity
- User Story: As a compliance officer, I want to export audit logs by date, user, or entity so that investigations are efficient.
- Acceptance Criteria:
  - Given filters, When applied, Then only matching audit entries are exported.
- Additional Details: Priority: High, Story Points: 2, Dependencies: User Story 1, Notes: For investigations.

User Story 4:
- Title: Test Coverage for Audit Logging
- User Story: As a QA engineer, I want automated tests to validate audit logging coverage so that compliance is ensured.
- Acceptance Criteria:
  - Given a test suite, When run, Then all sensitive actions are verified to generate audit logs.
- Additional Details: Priority: High, Story Points: 2, Dependencies: User Story 1, Notes: Automated tests.
