Title: Configure Spring Security with Role-Based Access

User Story: As a security administrator I want to configure Spring Security with role-based access control so that users can only access resources appropriate to their role.

Acceptance Criteria:

Scenario: Define user roles
Given the security configuration is implemented
When I inspect the role definitions
Then I should see ADMIN, HR, SUPERVISOR, and WORKER roles defined
And each role should have a clear hierarchy and permissions

Scenario: Protect endpoints with role requirements
Given endpoints are secured
When a WORKER user tries to access /api/v1/employees (list all)
Then access should be denied with 403 Forbidden
And only HR and ADMIN roles should have access

Scenario: ADMIN has full access
Given a user with ADMIN role is authenticated
When they access any endpoint
Then access should be granted
And they should be able to perform all CRUD operations

Scenario: SUPERVISOR has team-scoped access
Given a user with SUPERVISOR role is authenticated
When they access employee data
Then they should only see employees in their team/department
And they should not see employees from other teams

Scenario: WORKER has read-only self access
Given a user with WORKER role is authenticated
When they access employee data
Then they should only see their own employee record
And they should not be able to modify it

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Project scaffolding (E01), Employee entity (E02)
- Notes: Use method-level security annotations. Implement custom access decision voters for row-level security. Document role permissions clearly.
