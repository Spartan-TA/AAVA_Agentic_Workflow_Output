### E08 - Safety Incidents & OSHA Reporting

#### User Story 1
Title: Record Safety Incident
User Story: As a SUPERVISOR I want to record safety incidents with severity, location, description, and involved employees So that safety data is captured.
Acceptance Criteria:
Scenario: Incident Recording
Given SUPERVISOR is authenticated
When SUPERVISOR submits POST /safety/incidents
Then incident is validated and stored
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02, E03
- Notes: Validation required.

#### User Story 2
Title: Incident Investigation Workflow
User Story: As a Safety Officer I want to manage investigation and corrective actions So that incidents are resolved.
Acceptance Criteria:
Scenario: Investigation Workflow
Given incident is Open
When status changes to Investigating
Then corrective actions can be assigned
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02, E03
- Notes: Status workflow enforced.

#### User Story 3
Title: OSHA Summary Export
User Story: As an HR I want to export OSHA 300/300A fields So that regulatory reporting is supported.
Acceptance Criteria:
Scenario: OSHA Export
Given incident data exists
When HR requests export
Then OSHA fields are included
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E02, E03
- Notes: Format matches OSHA requirements.
