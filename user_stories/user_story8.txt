# E08: Safety Incidents & OSHA Reporting

## User Story 1
- Title: Record Safety Incidents
- User Story: As a supervisor, I want to record safety incidents with severity, location, description, and involved employees so that incidents are tracked.
- Acceptance Criteria in Gherkin format:
  Scenario: Incident recording
  Given a safety incident
  When I submit the incident via POST /safety/incidents
  Then the incident is validated and saved
- Additional Details:
  * Priority: High
  * Story Points: 3
  * Dependencies: E02, E03
  * Notes: Support near-miss and actual incidents

## User Story 2
- Title: Incident Investigation Workflow
- User Story: As a safety officer, I want a workflow for incident investigation and corrective actions so that incidents are resolved.
- Acceptance Criteria in Gherkin format:
  Scenario: Investigation workflow
  Given an open incident
  When the status is updated to Investigating or Resolved
  Then the workflow progresses and actions are logged
- Additional Details:
  * Priority: High
  * Story Points: 3
  * Dependencies: Incident records
  * Notes: Track corrective actions

## User Story 3
- Title: OSHA Report Generation
- User Story: As a compliance officer, I want to generate OSHA summary reports so that regulatory requirements are met.
- Acceptance Criteria in Gherkin format:
  Scenario: OSHA report export
  Given incident data
  When I request an OSHA 300/300A report
  Then the report is generated with required fields
- Additional Details:
  * Priority: High
  * Story Points: 2
  * Dependencies: Incident records
  * Notes: Export as CSV/PDF

## User Story 4
- Title: Safety Metrics Dashboard
- User Story: As a manager, I want a dashboard of safety metrics so that I can monitor KPIs.
- Acceptance Criteria in Gherkin format:
  Scenario: Metrics dashboard
  Given incident data
  When I access the dashboard endpoint
  Then safety KPIs are displayed
- Additional Details:
  * Priority: High
  * Story Points: 2
  * Dependencies: Incident records
  * Notes: Role-based access
