### E08 - Safety Incidents & OSHA Reporting

**User Story 1**
Title: Record Safety Incidents and Near-Misses
User Story: As a supervisor I want to record incidents with severity, location, description, and involved employees So that safety issues are tracked.
Acceptance Criteria:
Scenario: Incident record created
Given I have supervisor access
When I submit an incident report
Then the incident is stored with all required fields
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E02, E03
- Notes: Validate required fields

**User Story 2**
Title: Manage Incident Status Workflow
User Story: As a safety officer I want incidents to progress through Open, Investigating, and Resolved statuses So that investigations are tracked.
Acceptance Criteria:
Scenario: Status workflow
Given an incident is reported
When I update the status
Then the workflow transitions are enforced
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: E08-1
- Notes: Only authorized roles can change status

**User Story 3**
Title: Export OSHA 300/300A Summary
User Story: As a compliance officer I want to export OSHA summary fields So that regulatory reporting is simplified.
Acceptance Criteria:
Scenario: OSHA export
Given incidents are recorded
When I request an OSHA export
Then a file is generated with required fields
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E08-1
- Notes: Format per OSHA requirements

**User Story 4**
Title: Provide Safety Metrics Dashboard
User Story: As a manager I want to view safety KPIs via dashboard endpoints So that I can monitor trends.
Acceptance Criteria:
Scenario: Metrics dashboard
Given incidents exist
When I access the dashboard
Then I see metrics such as incident rate and resolution time
Additional Details:
- Priority: High
- Story Points: 1
- Dependencies: E08-1
- Notes: Endpoints available for BI integration
