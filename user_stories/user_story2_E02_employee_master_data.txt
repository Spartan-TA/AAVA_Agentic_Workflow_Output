**E02: Employee Master Data (CRUD)**

1. Title: Create Employee Record
User Story: As an HR user, I want to create a new employee record with name, badgeId, role, department, shiftGroup, hireDate, and status so that employee data is centrally managed.
Acceptance Criteria:
Scenario: Employee Creation
Given valid employee data
When I POST to /employees
Then a new employee is created with a unique badgeId
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: E01
- Notes: Validate badgeId uniqueness.

2. Title: Update Employee Details
User Story: As an HR user, I want to update employee details so that records remain accurate and current.
Acceptance Criteria:
Scenario: Employee Update
Given an existing employee
When I PUT/PATCH to /employees/{id}
Then the employee details are updated
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Story 1
- Notes: Audit changes.

3. Title: Delete (Soft) Employee Record
User Story: As an HR user, I want to soft-delete an employee record so that historical data is preserved but inactive employees are hidden.
Acceptance Criteria:
Scenario: Employee Soft-Delete
Given an active employee
When I DELETE /employees/{id}
Then the employee status is set to inactive and record is excluded from active lists
Additional Details:
- Priority: High
- Story Points: 2
- Dependencies: Story 1
- Notes: No hard deletes.

4. Title: List & Filter Employees
User Story: As a supervisor, I want to list and filter employees by department, role, and status so that I can quickly find relevant staff.
Acceptance Criteria:
Scenario: Employee Listing
Given multiple employee records
When I GET /employees with filters
Then only matching employees are returned with pagination
Additional Details:
- Priority: High
- Story Points: 3
- Dependencies: Story 1
- Notes: Support OpenAPI schemas.
