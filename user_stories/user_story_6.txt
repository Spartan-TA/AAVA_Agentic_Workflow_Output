Title: Create Employee Domain and CRUD APIs

User Story: As an HR manager I want to manage employee records via CRUD APIs So that employee data is accurate and up to date.

Acceptance Criteria:
Scenario: Create employee
  Given valid employee data
  When I POST to /employees
  Then a new employee record is created
Scenario: Read employee
  Given existing employees
  When I GET /employees/{id}
  Then the correct employee data is returned
Scenario: Update employee
  Given an existing employee
  When I PUT/PATCH to /employees/{id}
  Then the employee record is updated
Scenario: Delete employee
  Given an existing employee
  When I DELETE /employees/{id}
  Then the employee record is soft-deleted

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: user_story_1.txt, user_story_2.txt
- Notes: API must support pagination and filtering; OpenAPI schemas required.
