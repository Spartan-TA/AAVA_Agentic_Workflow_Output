Title: Employee API Pagination, Filtering, and OpenAPI Documentation

User Story: As a developer I want to implement pagination, filtering, and OpenAPI schema documentation for employee APIs So that consumers can efficiently query employee records and understand API usage.

Acceptance Criteria:
Scenario: Paginated employee list
  Given multiple employee records exist
  When I GET /employees with pagination parameters
  Then the response should be paginated
Scenario: Filter employee records
  Given employee records exist
  When I GET /employees with filter parameters (e.g., department, role, status)
  Then only matching records should be returned
Scenario: OpenAPI schema availability
  Given the API is deployed
  When I access the OpenAPI documentation
  Then employee endpoints should be documented with request/response examples

Additional Details:
- Priority: High
- Story Points: 5
- Dependencies: Employee CRUD APIs
- Notes: Ensure filters cover all major fields and documentation is up-to-date.
